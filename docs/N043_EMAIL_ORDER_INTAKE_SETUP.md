# N043 邮箱自动收单：管理员一次性设置

## 最终业务流程

```text
客户发邮件并附 PDF / Excel 订单
→ Windows 每 30 分钟安全收取一次
→ ERP 记录邮件和附件
→ 根据完整发件人邮箱推荐客户
→ 生成待人工核对草稿
→ 管理员核对客户、产品、数量、单价
→ 明确确认后才创建正式订单
```

邮箱收取本身绝不会自动创建正式订单。

> 发件地址映射只用于推荐客户，不代表系统已经验证发件人的真实身份。操作员仍需核对邮件主题、附件内容和客户后，才能保存正式订单。

## 第一次设置

1. 准备一个只用于 ERP 收订单的邮箱，并在邮箱后台开启 IMAP。
2. 建议使用邮箱提供商生成的“客户端授权密码”，不要使用网页登录密码。
3. 在项目目录打开 PowerShell，执行：

```powershell
.\scripts\windows\configure_email_order_intake.ps1
```

4. 按提示填写 IMAP 服务器、邮箱地址和授权密码。
5. 重启 ERP 后，执行：

```powershell
.\scripts\windows\install_email_order_intake_task.ps1
```

计划任务默认每 30 分钟运行一次；密码不会写入 Git、任务命令行或网页。
安装时会解析并固定一个 `python.exe` 绝对路径；运行任务不再依赖系统中任意的 `py`。如果项目使用专用虚拟环境，可明确执行：

```powershell
.\scripts\windows\install_email_order_intake_task.ps1 -PythonExecutable "D:\路径\到\python.exe"
```

当前采用登录用户计划任务，因此 ERP 电脑需要保持该 Windows 用户登录。

## ERP 中的日常操作

1. 打开“订单管理 → 邮箱订单草稿”。
2. 在“发件人 → 客户映射”中登记客户实际发件邮箱。
3. 点击“立即收取”可手工测试；日常无需点击，系统每 30 分钟运行。
4. “收件记录”显示所有成功、失败、不支持和重复附件。
5. “识别草稿”只显示可以继续人工处理的订单草稿。
6. 打开草稿并核对完成后，才能保存正式订单。

## 安全边界

- 只登记完整发件邮箱，不允许用整个邮箱域名模糊匹配。
- 不支持的附件也保留收件记录和失败原因。
- 超大邮件、附件过多、可疑压缩文件和超页数 PDF 会被拒绝。
- 每次 IMAP 操作及整轮手工收取都有明确超时，超时会安全结束并记录失败，不会无限占用服务。
- 未显式配置 `ERP_EMAIL_INTAKE_MAILBOX_KEY` 时，系统会根据 IMAP 主机、账号和文件夹生成不含敏感原文的稳定摘要，避免不同邮箱 UID 冲突。
- 同一邮件重复拉取不会重复建草稿。
- 同一邮箱草稿最多只能创建一张正式订单。
- 正式启用前必须使用专用测试邮箱和数据库副本完成验收。

## 常见问题

- 不知道 IMAP 地址：在邮箱服务商的“客户端 / IMAP”帮助页查询，并先开启 IMAP 服务。
- 普通密码登录失败：多数邮箱要求使用单独生成的“授权密码”，不是网页登录密码。
- 查看任务：打开 Windows“任务计划程序”，搜索 `Tianming ERP Email Order Intake`。
- 查看收件日志：打开项目下 `logs/email_order_intake_scheduler.log`。
- 授权密码失效：重新运行 `configure_email_order_intake.ps1`，再手动运行一次计划任务验证。
- 页面没有新邮件：先看 ERP 的“订单管理 → 邮箱订单草稿 → 收件记录”，再检查日志中的中文错误。
