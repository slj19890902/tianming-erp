## 2. 推荐方向

后续最适合两位主要操作者的方向仍是：

> 方向 A：轻立体楼层导视 + 精确二维作业图 + 固定右侧详情。

轻立体只帮助判断“一楼还是三楼”，进入具体仓区后立即使用准确二维图。日常入口不使用自由旋转 3D，也不在透视图中堆放小字。

方向 B 是低风险的楼层卡片对照；方向 C 是高查询密度控制台对照，不建议默认给两位日常操作者。

## 5. 仓库下钻契约

统一层级：

`厂区总览 → 楼层 → 仓区/区域 → 库位 → 固定详情`

- 厂区总览：只显示真实已接入状态和建设状态。
- 三楼：进入精确二维作业图。
- 区域：放大真实区域；地堆俯视，货架使用正立面。
- 库位：空位只显示“当前位空闲”和“绑定货物（原型演示）”；占用位显示匿名栈板和数量。
- 一楼：只显示台账建设中，不生成区域、库位或库存。
- admin 入口：只解释草稿、预览、发布、占用校验、版本和历史门禁；所有按钮均为不会保存的演示。

面包屑必须能逐级返回，不能依赖浏览器后退，也不能因为下钻销毁订单、报料或来料页面的状态。

## 6. 三套方向

### 方向 A：轻立体楼层导视（推荐）

- 厂区总览用不可旋转的 3F/1F 轻立体层板。
- 三楼一键进入精确二维图。
- 学习成本低，空间关系最直观。

### 方向 B：楼层卡片 + 二维缩略图

- 三楼、一楼分别使用普通卡片。
- 风险最低，最接近现有 ERP。
- 空间辨识度低于方向 A。

### 方向 C：空间控制台

- 左侧楼层/区域树，中间二维图，右侧异常和当前库位。
- 查询密度最高。
- 对两位日常操作者可能信息过多，不建议默认。

## 7. 权限和写操作边界

- 原型所有“绑定货物、移动栈板、进入操作记录、预览布局草稿、新建受控变更”等按钮只显示“原型演示，不会保存”。
- 正式地图的绑定、移动、归位、布局维护继续使用现有权限、客户范围、目标空位、库存状态、版本、幂等和审计门禁。
- 入口合并不能让拥有订单权限的账号自动获得仓库权限。
- 地图右栏不能增加绕过正式事务的快捷数量修改。
- 一楼、D2、原料、模具和挂板在真实模型/资料建立前不能产生可点击的正式写入口。
