## 3. 三角色当前差距与目标矩阵

### 3.1 当前权限事实

- `admin`：当前拥有全部权限，并具有全客户范围。
- `delivery_picker`：默认只有 `orders.view` 和 `deliveries.pick`，没有
  `warehouse.view`。
- `workshop`：当前默认有订单、来料、仓库和送货查看，以及来料、仓库写权限；
  生产读写仍复用 `orders.view/orders.status`，没有独立 `production.view`。

因此原型中的“送货员本人任务”和“生产员工本人生产资料”是目标交互，不是当前已
具备的服务端授权事实。P1-21B～D 在真正接入前必须补齐任务归属或最小专用读取门禁，
不能仅根据前端角色名称过滤。

### 3.2 字段、动作和 API 目标

| 角色 | 最小可见字段 | 第一阶段允许动作 | 必须隐藏 | 未来 API/权限要求 |
|---|---|---|---|---|
| `admin` | 客户、存货编码、产品、规格；成品/半成品/原料分单位数量；全部有权位置；今日业务摘要 | 搜索、选择候选、展开位置、地图聚焦、安全返回 | 密码、令牌；默认不在产品查找页展示成本和财务 | P1-21B 新增只读产品聚合；复用现有权限和客户范围 |
| 送货员 | 当前拿货任务、客户、编码、产品、本次应拿量、本人任务内的位置/栈板 | 进入任务、查看数量和位置、地图聚焦、返回；正式动作继续复用 N083 | 单价、成本、对账、图纸、其他客户、同库位无关库存、全仓搜索 | P1-21C 必须做任务级受控响应；不得授予全仓 `warehouse.view` |

## 4. 产品反查与数量契约

产品身份必须至少包含：

```text
customer_id + product_id + 存货编码 + 产品名称 + 规格
```

多候选时必须人工选择，不允许自动进入首条。数量必须分栏并带单位：

- 成品：总量、可用、预占、待拿，单位为“只”；
- 半成品：按其正式单位单列，例如“张”；
- 原料：只有存在正式原料仓事实时才展示；当前原料仓未建立，不能用 `0` 冒充
  “已经查过且没有库存”，也不能和成品/半成品相加；
- 各位置数量之和必须与同类型摘要可对账；
- 待归位、未布局、生产区直接拿货和独立模具位置使用文字降级，不伪造地图点。

## 5. 搜索/任务 → 地图 → 返回契约

1. 保留入口来源：产品搜索、拿货任务或生产资料。
2. 保留关键词、明确选择的产品/任务、展开位置、滚动位置和当前聚焦点。
3. 地图默认同时显示该产品/任务的全部可绘制真实位置。
4. 点击一个位置只改变聚焦，不丢弃其他位置标记。
5. 无坐标位置继续在地图下方以文字列出。
6. 固定返回按钮回到原入口并恢复上述状态。
7. 返回不得重新请求后自动选择首个候选；旧响应不得覆盖新关键词。

## 6. 权限与直接请求 fail-closed 契约

| 请求类型 | 服务端前置门禁 | 拒绝时要求 |
|---|---|---|
| 搜索候选/数量 | 登录、最小读取权限、客户范围先过滤 | 不泄露候选数、产品名、数量或位置数 |
| 产品/订单直接 ID | 读取实体后再次执行客户范围 | 统一拒绝；不能靠不同错误文案枚举其他客户 |
| 地图与位置详情 | 通用查询需 `warehouse.view`；送货员使用本人任务专用响应 | 不返回同库位其他客户或整库位内容 |
| 拿货任务 | `deliveries.pick` + 客户范围 + 未来任务归属 | 任务列表、详情、数量和地图都使用同一范围 |
| 生产资料 | 未来最小生产读取权限 + 客户/任务范围 | 不借 `workshop` 宽权限开放写接口 |
| 图纸附件 | 对应订单/产品读取权限 + 客户范围 + 私有 `no-store` | 不产生永久公共 URL，不缓存到离线应用 |

## 7. 页面状态契约

原型固定演示以下互不混淆的状态：

- `loading`：正在读取，不能显示“没有数据”；
- `empty`：成功读取且确实无结果；
- `error`：服务失败，可重试；
- `permission-denied`：无权限，不展示任何候选、数量或位置；
- `stale`：数据已过期，只能刷新，不允许继续正式动作；
- `no-location`：数量事实存在，但没有可绘制位置，使用文字降级；
- `offline/weak-network`：未得到服务端成功结果，不乐观显示完成；
- 多候选：保留输入，必须人工选择。

P1-21A 原型不会触发真实请求；“重试”和“刷新”只切换匿名演示状态。

## 8. P1-21B～D 实施前门禁

1. 先决定 P1-16 的唯一地图方向；本原型只使用轻量二维作业图，不建立第二套地图。
2. 为送货任务建立能够证明“本人任务”的服务端事实，或明确采用受客户范围约束的
   共享任务口径；未确认前不得写成严格本人任务。
3. 为生产员工建立最小只读权限，不直接复制当前 `workshop` 宽权限。
4. 建立单一产品库存聚合服务，复用现有批次/位置求和，不从地图分页结果反推总量。
5. 原料仓未建立前，原料栏明确显示“尚无正式原料仓数据”，不能开放原料写操作。
6. 任何正式写动作继续复用既有幂等、版本、事务和审计；手机查看不等于完工、
   收料、移位或发货。
