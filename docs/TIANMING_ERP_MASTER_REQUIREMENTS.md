## 4. 系统定位和主流程

系统服务三级纸箱厂，核心是把状态流转管清楚，不建设大型 SAP、复杂会计或重复仓库账。

主流程：

`报价 → 下单 → 报料 → 材料到达 → 自动生产/成品 → 送货 → 回单 → 月结对账 → 开票 → 收款`

每个环节必须保留来源、数量、状态和审计。禁止无来源跳状态，例如未报料不能标材料到达、未送货不能回单、未回单不能正式对账、已作废单据不能继续产生下游事实。

库存和地图只为主流程提供真实数量、位置和追溯，不发展成与订单主链分离的第二套复杂 WMS。

## 5. 现场操作和确认原则

工厂主要由少量文员和管理人员操作电脑，默认少输入、少弹窗、少切换、少填原因。

普通保存、新增、收料、打印、筛选、查询、地图移库和自动完工不二次确认。以下操作确认一次：删除、作废、撤销收料/完工/发货、覆盖历史事实、批量修复正式数据、重复打印、实际成品高于理论。普通业务不填原因；取消、关闭、ESC 或遮罩不得执行。

正式页面不得混入模拟业务数据。模拟数据只存在于测试和隔离 UAT；正式空页面显示明确空状态。

## 6. 报料采购用途分配

### 6.1 核心关系

报料草稿在正式供应商采购单生成前冻结：

`订单生产用途纸板数量 + 客户通用片料备库数量 = 本次采购总纸板数量`

必须分别显示订单成品数量、订单生产所需纸板数量、本次采购总纸板数量、订单用途纸板数量和备库用途纸板数量，单位不能混写。

示例：订单500只，一张出一只，采购600张，则订单用途500张、备库100张。若一张出两只，订单500只需要250张，采购300张，则订单用途250张、备库50张，理论成品仍为500只。

### 6.2 操作位置和默认值

用途分配发生于：

`待报料 → 系统计算 → 报料草稿 → 调整采购数量 → 自动形成用途差额 → 确认正式采购单`

默认订单用途等于系统计算的订单所需纸板，备库用途等于采购总量减订单用途。允许人工调整，但必须实时校验守恒。不得在订单录入时强制填写，也不得等到收料后猜测。

供应商采购单只显示供应商需要的采购总量；用途拆分是 ERP 内部冻结事实。生产任务只使用订单用途，不包含备库数量。

### 6.3 分批收料

2026-09-14补库实收补充：供应商多送或少送按实际收料数量登记，原报料数不变。补库多送片料随本次实收统一入原料暂存位，保留差额及实际价格快照；少收可继续等补料或明确按已收数结单，不再补料。短收结清的未收到数量不形成库存、成本或在途覆盖；不自动修改历史收料。

存在明确用途分配时，累计有效收料先满足订单用途，超过部分进入同一客户备库：

- 实收450：订单用途450，备库0；
- 实收580：订单用途500，备库80；
- 实收600：订单用途500，备库100；
- 实收620：订单用途500，备库120，显示计划100、实际120、差异+20。

没有设置备库用途的历史和普通报料继续沿用原普通收料口径，不因新功能全局改变。

### 6.4 备库库存性质和匹配

2026-09-14补库换算确认：预警的目标成品数与采购片料张数分开；报料按成品数×每箱/每套片数，扣除实际可抵扣片数后，再除已确认开料出数向上取整。双拼141个、一开一为282片；模具最大出数不是当前实际开料出数。材料库存预警直接按片料张数，不重复乘每箱片数。组装消耗型BOM实际完成组套后按父件套数及成套位置找货，不重复领取已消耗子件；历史单据不自动回写。

备库是客户专用通用半成品片料，不是当前订单成品、当前存货编码专用成品、可直接送货成品或自动跨客户库存。

至少保存客户、来源订单/报料/采购/收料、供应商、实际材质、楞型、层数、纸板长宽、压线、净片/毛片、数量、成本、实际位置和时间。

默认匹配：同客户、同纸板长宽、同楞型、同层数、同材质、同压线、同净片/毛片及相同换算事实。以后新订单只显示候选，人工确认后形成预占并减少采购需求，仍需生产。跨客户只可作为高级候选，显著提示且人工确认，绝不自动使用。

2026-09-14 PDF订单抵扣交互补充：同客户、完全匹配且后端明确可直接抵扣的安全片料及成品可自动安排；需要核对的候选，操作员点击该候选“采用”即确认其差异，不再额外勾选。采用确认须随同具体批次保存和库存刷新保留，不等于确认其他风险候选；跨客户库存仍不自动采用。实际保存继续核对客户范围、数量、版本、幂等、事务和审计，不因减少页面操作取消这些校验。

- 地图材料候选用途（2026-09-10）：选中原材料/半成品片料可反向匹配所有有权限查看客户的常用箱，同楞型同层数、长宽可容纳且不旋转；报料长宽完全一致优先，其次按裁切面积利用率降序，支持客户/编码筛选。匹配度超过70%且面纸不冲突的候选可由管理员保存。保存候选本身不形成产品绑定或预占；正式适用范围通过独立的人工用途维护确认。

### 6.5 成本、撤销和追溯

采购总成本按实际用途数量拆为订单材料成本和片料库存成本，二者合计等于采购总成本。实际材质变化后按权威价格重算，不改变客户订单销售数量和金额。

实际采购价格的权威来源是材质主档中该实际材质经授权维护的采购价格合同；`materials.quote_price`、`price_unit`、`purchase_currency`、`purchase_tax_included` 和 `purchase_tax_rate` 共同组成该合同，`materials.rule_base_price` 仅作报价规则参考。正式收料价格事实至少冻结来源明细、材料身份、币种、价格单位、含税/未税口径、税率、最终单位价格、确认人、确认时间和版本，不能假设所有价格使用同一单位或同一税口径，也不能由后续主档改价反推或覆盖历史收料价。

每条正式收料行确认时冻结当时有效的采购价格合同和实际材质。首次收料前，具有价格录入权限的办公室人员或管理员在材质主档维护价格、币种、税费口径和税率；正常实收无需逐行点击处理价格。发生收料后可以维护主档用于未来收料，但不得直接覆盖历史收料快照。价格纠错必须通过受控更正动作保留修改前后、原因、操作人、时间、版本和明确影响范围。

实际到料材质与正式报料材质不同时，收料人员只能发起异常、选择实际材质并填写原因；具有异常确认权限的办公室人员或管理员确认后，系统按所选实际材质主档价格合同重算并冻结本条收料，才能正式入账。系统必须同时冻结报料材质、实际材质、差异原因、价格合同和确认人，不静默修改产品主档、订单快照或历史报料。材质价格维护、异常确认和价格更正分别使用明确后端权限；普通财务角色可以查看和审计价格事实。

撤销收料必须按该次实际用途精确反向：订单用途反冲成品和生产事实，备库用途反冲片料批次。已送货、已预占、已生产使用或已产生其他下游事实时阻止撤销，先撤销下游。

全链必须能从来源订单追到用途、采购、收料、订单成品或片料批次，再追到未来使用订单；禁止按名称或编码文本猜关联。

## 7. 收料后自动生产和成品流转

### 7.1 生产任务唯一性

一个订单明细对应一个持续存在的生产任务和一个稳定二维码。部分收料不重复建任务，重复打印不建任务，同编码新订单建立新任务。备库用途不为当前订单增加第二个成品任务。

### 7.2 普通自动流转

随货配套补充（老板2026-09-15确认）：父件生产与子件独立报料、独立入庫不解除BOM配套关系。订单冻结的随货子件按送货父件数量乘每套用量分别预占、原位扣库，撤销恢复原来源；客户送货单可隐藏子件，但仓库找货与实物标签不能隐藏。组装消耗子件不再次随父件扣库。扫码可查父子件关系和库存位置，当前主档关系不冒充订单预占。历史缺失预占、订单版本切换与库存转换另行处理，新发货不得悄悄补扣历史差额或仅扣父件成功。

2026-09-14 外购包材补充：普通纯外购包材不需要生产，按冻结订单采购比例累计换算，实收即成品入仓并预占到来源订单；送货及改量使用同一库存流水。灰底白卡（coated_board）保留原料流程；附属组件、真实多级BOM和明确备库仍遵守各自冻结合同。历史已收未入仓事实不自动补写，另行核对处理。

组合BOM插合例外（老板2026-09-15补充，以本条为准）：订单与备库中未组套的已加工组装子件都应在待组套展示，缺件也显示数量、原位置和缺口；未预占备库单独列示，配比参考不等于实物已经组装或通过身份校验。新订单自动预留同客户、同产品及冻结实物身份完全匹配的已加工库存，减少对应报料需求。订单用途新收料生产的长短片同样按该订单需要进入待组套；通用片料和身份不明批次不自动使用。配齐不代表已经插合，现场插合完成后确认一次实际套数及成套位置，事务内消耗长短片、增加成套库存、继承来源成本。允许分批确认，未组装余片保持子件和原位置；配套与子件交货不强制组装。既有组装流水不因这项新流程自动撤销或重写。

无印刷且无需模切等加工的普通衬板，以已采用并预占、一张对应一件且尺寸合适的净片半成品抵扣全部需求时，按原批次原位置直接出货，不重复进入生产、完工入库或选择新货位。实际库存材质可以与常用箱/订单不同，已有人工采用差异确认不能因当前主档材质再次失效；实际材质及成本保持原批次，不改写为常用箱材质。客户适用范围、实物加工条件和预占身份仍须校验。原料需切割、比例换算、印刷、模切或不足覆盖部分仍走正常生产。出货与撤销沿用原预占、成本和流水，不伪造完工记录。

订单用途每次收料后在同一受控事务中：

`保存实收和实际材质/价格快照 → 重算材料成本 → 更新累计来料 → 按开料/拼版计算理论成品 → 更新实际成品默认值 → 写完工增量 → 增加成品库存 → 进入一楼成品待送暂存组内一个满足策略和容量的实际成员区域 → 立即可送货`

不要求人工点击开始生产、印刷完成、模切完成、确认完工或选择默认位置。备库用途只增加片料库存，不生成当前订单成品、可送数量或完成状态。

### 7.3 理论与实际数量

备库补货跟踪补充（老板2026-09-12确认）：采购确认后在4生产保留待来料记录，实收批次在原库存和实际位置上显示待安排，不重复入库。管理员可将可用材料的一部分或全部安排待生产，先预占材料；确认实际产出时原子消耗投入、增加成品并登记实际位置，取消未完工安排恢复可用材料。也可确认保留原料或半成品备货用途，等待订单抵扣；用途确认不重写采购、收料及材质加工事实。原收料、安排、库存流转和成品余货持续可追溯，历史批次直接投影，无自动补建生产或完成事实。普通订单原自动流转不变。

## 16. 全链路追溯和财务

- 订单用途绑定唯一生产任务；备库用途绑定片料库存分配记录，不增加当前订单成品任务。
- 采购成本必须拆分，不得把全部采购成本归入订单。
- 备库片料不能直接送货，只有生产成具体产品成品后才能送。
- 订单成品和片料位置分开，临时共用成品区域时库存类型不得改变。
- P1-11D 保持暂停。
- P1-46A、P1-47D、P1-71、P1-72A/B/C、P1-74 等未正式候选须在开发前重新核对最新正式版、patch-id、迁移和本总需求；禁止直接整分支合入。
- 已正式或等价整合的能力不得重复开发。

## 19. 实施顺序和专项验收

1. P0：正式构建资源闭合、紧急五对象及全量未完成订单只读扫描，并先收口审计发现的业务口径冲突。
2. P1：按独立闭环依次完成工位路由、常用箱颜色保存链、独立产品标签等紧急回归；历史补数不与代码修复混做。
3. 采购用途分配及冻结。
4. 收料用途分流、自动成品、片料库存、成本和撤销。
5. 地图、栈板、位置和追溯闭环。
6. 打印和二维码。
7. 电脑端、手机端和模具管理。
8. 工厂隔离副本 dry-run、正式发布包和人工验收。

用途分配金样本必须覆盖：500/600、实收450、580、600、620、一张出两个、无备库用途、撤销阻断、成本守恒及双向追溯。

每阶段独立分支、独立提交、独立测试、独立回执。阶段完成不等于正式上线；候选推送后仍需工厂受控整合和人工验收。

## 20. 完成定义

只有同时满足以下条件才算本总任务达成：

- 冲突已按老板确认规则处理；
- 活动 P0/P1 去重后全部完成，暂停任务和工厂待执行项明确隔离；
- 订单数量、采购张数、拼版产出和备库张数不混淆；
- 订单用途与片料备库分别入账、计成本、定位和追溯；
- 自动生产、撤销、送货、库存和异常链守恒；
- 仓库地图使用唯一位置和唯一栈板标准；
- 模具、打印、二维码、电脑和手机规则一致；
- 指定异常有根因和通用回归，不写死特殊编码；
- 自动化测试、构建、迁移副本演练、差异检查和外部验收记录齐全；
- 没有重复实现、文件冲突、静默历史改写或正式数据库越权写入；
- 每个候选已推送并写回 NAS 回执，工厂事项有独立可执行交接包。
