## 4. 系统定位和主流程

系统服务三级纸箱厂，核心是把状态流转管清楚，不建设大型 SAP、复杂会计或重复仓库账。

主流程：

`报价 → 下单 → 报料 → 材料到达 → 自动生产/成品 → 送货 → 回单 → 月结对账 → 开票 → 收款`

每个环节必须保留来源、数量、状态和审计。禁止无来源跳状态，例如未报料不能标材料到达、未送货不能回单、未回单不能正式对账、已作废单据不能继续产生下游事实。

库存和地图只为主流程提供真实数量、位置和追溯，不发展成与订单主链分离的第二套复杂 WMS。

## 5. 现场操作和确认原则

工厂主要由少量文员和管理人员操作电脑，默认少输入、少弹窗、少切换、少填原因。

普通保存、新增、收料、打印、筛选、查询、地图移库和自动完工不二次确认。以下操作确认一次：删除、作废、撤销收料/完工/发货、覆盖历史事实、批量修复正式数据、重复打印、实际成品高于理论。普通业务不填原因；取消、关闭、ESC 或遮罩不得执行。

正式页面不得混入模拟业务数据。模拟数据只存在于测试和隔离 UAT；正式空页面显示明确空状态。

## 6. 报料采购用途分配

### 6.1 核心关系

报料草稿在正式供应商采购单生成前冻结：

`订单生产用途纸板数量 + 客户通用片料备库数量 = 本次采购总纸板数量`

必须分别显示订单成品数量、订单生产所需纸板数量、本次采购总纸板数量、订单用途纸板数量和备库用途纸板数量，单位不能混写。

示例：订单500只，一张出一只，采购600张，则订单用途500张、备库100张。若一张出两只，订单500只需要250张，采购300张，则订单用途250张、备库50张，理论成品仍为500只。

### 6.2 操作位置和默认值

用途分配发生于：

`待报料 → 系统计算 → 报料草稿 → 调整采购数量 → 自动形成用途差额 → 确认正式采购单`

默认订单用途等于系统计算的订单所需纸板，备库用途等于采购总量减订单用途。允许人工调整，但必须实时校验守恒。不得在订单录入时强制填写，也不得等到收料后猜测。

供应商采购单只显示供应商需要的采购总量；用途拆分是 ERP 内部冻结事实。生产任务只使用订单用途，不包含备库数量。

### 6.3 分批收料

- 实收580：订单用途500，备库80；
- 实收600：订单用途500，备库100；
- 实收620：订单用途500，备库120，显示计划100、实际120、差异+20。

没有设置备库用途的历史和普通报料继续沿用原普通收料口径，不因新功能全局改变。

### 6.5 成本、撤销和追溯

采购总成本按实际用途数量拆为订单材料成本和片料库存成本，二者合计等于采购总成本。实际材质变化后按权威价格重算，不改变客户订单销售数量和金额。

实际采购价格的权威来源是材质主档中该实际材质经授权维护的采购价格合同；`materials.quote_price`、`price_unit`、`purchase_currency`、`purchase_tax_included` 和 `purchase_tax_rate` 共同组成该合同，`materials.rule_base_price` 仅作报价规则参考。正式收料价格事实至少冻结来源明细、材料身份、币种、价格单位、含税/未税口径、税率、最终单位价格、确认人、确认时间和版本，不能假设所有价格使用同一单位或同一税口径，也不能由后续主档改价反推或覆盖历史收料价。

每条正式收料行确认时冻结当时有效的采购价格合同和实际材质。首次收料前，具有价格录入权限的办公室人员或管理员在材质主档维护价格、币种、税费口径和税率；正常实收无需逐行点击处理价格。发生收料后可以维护主档用于未来收料，但不得直接覆盖历史收料快照。价格纠错必须通过受控更正动作保留修改前后、原因、操作人、时间、版本和明确影响范围。

实际到料材质与正式报料材质不同时，收料人员只能发起异常、选择实际材质并填写原因；具有异常确认权限的办公室人员或管理员确认后，系统按所选实际材质主档价格合同重算并冻结本条收料，才能正式入账。系统必须同时冻结报料材质、实际材质、差异原因、价格合同和确认人，不静默修改产品主档、订单快照或历史报料。材质价格维护、异常确认和价格更正分别使用明确后端权限；普通财务角色可以查看和审计价格事实。

撤销收料必须按该次实际用途精确反向：订单用途反冲成品和生产事实，备库用途反冲片料批次。已送货、已预占、已生产使用或已产生其他下游事实时阻止撤销，先撤销下游。

全链必须能从来源订单追到用途、采购、收料、订单成品或片料批次，再追到未来使用订单；禁止按名称或编码文本猜关联。
