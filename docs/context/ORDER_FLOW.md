# 订单主链上下文路由

适用：报价、客户/常用箱、订单录入、PDF/Excel、报料、来料、生产、送货、回单及状态投影。

## 必读路由

1. 当前任务卡。
2. NAS `02_业务流程\核心业务全流程.md` 中当前环节。
3. NAS 对应功能模块设计；只读取任务命中的标题段落。
4. 按任务编号、错误原文、接口或单号检索 NAS `04_开发记录\任务回执`。

## 代码入口

- 订单：`app/api/orders.py`、订单服务、`tests/test_phase5_orders.py`
- PDF/Excel：`app/services/order_pdf_import.py`、PDF/订单导入专项测试
- 报料/来料：`app/api/requisition.py`、来料与报料专项测试
- 生产/送货：生产、delivery API/服务及数量闭环测试
- 前端：先在 `static/index.html` 用页面 ID、函数名或接口路径定位，不得全文载入

## 必须保护的历史回归

- 状态由真实业务事实派生，未收料不得显示待生产，兄弟明细不得互相污染。
- 双拼投入片数与成品只数必须按冻结 `pieces_per_box` 换算，不能把 60 片写成 60 只。
- 已撤销的生产完工不得计入有效组件抵扣；只统计有效 posted 事实。
- PDF/Excel 识别只形成草稿；完整性、客户范围、人工确认和库存候选新鲜度不得绕过。
- 手工尺寸且尚无正式 `product_id` 的行不得继承过期库存草稿；正式产品仍保留库存版本门禁。
- 送货取消后的历史库存分配和正反流水必须保留；有历史事实的单据不得因删除暴露 500。
- 回单确认后才能正式对账；对账金额基于确认数量；对账、开票、收款不得越级。

## 最小验证

先运行本任务失败用例，再运行当前接口/服务专项和相邻数量状态测试。若改共享前端函数，补普通新建订单、PDF 草稿和已有订单三条路径中的适用回归。
