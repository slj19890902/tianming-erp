## 3. 明天现场使用前的部署建议

如果工厂电脑需要直接打开网页并登录操作，推荐方案只有一个：

### 方案：工厂电脑本机运行 ERP

在工厂电脑本机启动：

```powershell
.\start_erp.bat
```

然后本机浏览器打开：

```text
http://127.0.0.1:8000
```

不要优先走“跨公网访问另一台电脑上的 ERP 页面”。

原因：

- 两台电脑不在同一局域网
- 明天要稳定可登录、可编辑、可打印
- SQLite 本地运行最稳

如果工厂电脑目录不同，必须同步修正 `.env` 中的：

- `ERP_DATABASE_PATH`
- `ERP_BACKUP_DIR`

## 4. 当前已知运行态问题

### 4.1 8000 端口旧进程问题

当前现场很可能存在一个旧 Python 进程占用 8000，表现为：

- 页面部分是新代码
- 但某些后端接口仍是旧内存代码
- 导致前后端不一致

已确认过的典型症状：

1. 点击 `收款核销` 仍报“收款账户不能为空”或右下角红字。
2. 点击 `识别预览草稿` 没反应或接口失败。

根因不是数据库，而是旧进程未重启。

### 4.2 处理方式

如果工厂电脑上出现“页面像更新了，但接口行为像旧版”的情况，先做：

1. 结束旧的 `python.exe` / `uvicorn` 进程
2. 重新运行：

```powershell
.\start_erp.bat
```

3. 浏览器按 `Ctrl + F5` 强制刷新

- `sales_order_items.item_order_number`
- `sales_order_items.item_sequence`

### 5.3 订单管理分组规则

默认分组：

```text
group_key = customer_id + customer_po
```

规则：

- 同一客户 + 同一客户单号才合并
- 不同客户即使客户单号相同也不能合并
- `customer_po` 为空时不合并
- 系统单号默认隐藏，展开后显示

### 5.4 已有订单的历史归档口径

当前已有老订单已统一进入历史查看口径：

- 不再进待报料池

- 仅用于历史查询/模拟/参考

## 6. 工厂电脑上的 Codex 下一步要做的核心任务

当前下一大块工作不是历史迁移，而是：

## “订单识别、新建订单、订单状态与成本显示流程优化”

重点要求如下。

### 6.1 订单识别草稿流要重做

当前问题：

- 识别后保存提示“第1条请先选择产品”
- 自动客户匹配不稳定
- 手动选客户会把识别内容清空

目标流程应改成：

```text
上传 / 识别订单
→ 生成识别草稿
→ 自动匹配客户
→ 自动匹配产品 / 材质 / 尺寸
→ 未匹配项人工确认
→ 保存正式订单
```

要求：

- 草稿状态前端独立保存
- 手动换客户不能清空已识别内容
- 只重新跑产品候选匹配
- 未匹配产品要显示“待匹配”而不是直接报错

### 6.2 识别字段修正

必须按下面映射修：

- 存货编码 ← 订单里的存货编码/物料编码
- 物料名称 ← 订单里的物料名称
- 规格型号 ← 订单里的规格型号
- 数量 ← 订单数量
- 客户单号 ← 客户订单号 / PO号

不要把“白底黑字内箱”这种描述误当作主物料名称，除非它确实来自物料名称字段。

### 6.3 多文件识别 + 防重复识别

需要加：

- 一次上传多个订单文件
- 单文件失败不影响其他文件
- 文件级识别状态
- 重复订单跳过
- 显示重复原因

### 6.4 成本显示

建议本轮实现：

在新建订单明细中显示：

- 客户单价
- 预估成本
- 预估毛利

不要先把成本塞进对账主表。

### 6.5 订单状态与数量统计

订单管理顶部数量只显示“未完成订单”。

不计入数量的状态：

- 已完成
- 已归档
- 已结档
- 已作废
- 已取消
- 死单

默认筛选建议：

```text
未完成
```

### 6.6 删除订单 / 死单 / 手动结单

需要新增：

- 编辑里允许“删除订单”
- 但如果已有送货/开票/收款关联，不允许直接删
- 只允许作废/已结档/死单
- 死单或手动结单必须填写备注原因
