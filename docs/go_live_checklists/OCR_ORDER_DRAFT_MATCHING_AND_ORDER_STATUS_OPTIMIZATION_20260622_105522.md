## 2. 实施闭环

### 2.1 OCR 独立草稿流

已完成：

- 前端新增 `orderImportBatch`、`orderImportDrafts[]` 和逐行草稿数据。
- 识别结果先进入草稿，不直接覆盖正式 `orderForm`。
- 草稿保留文件名、文件 hash、客户识别原文、客户匹配、客户单号、日期、状态、重复状态、明细和 warnings。
- 手动选择或更换客户时保留存货编码、物料名称、规格型号、数量和单价，只刷新产品、材质候选和成本参考。
- 客户匹配返回 `matched`、`multiple_candidates`、`unmatched`。
- 保存前逐行显示中文缺失项提示，不展示原始 JSON 错误。

结论：OCR 草稿流完成；手动选择客户不再清空识别内容；自动客户匹配完成。

### 2.2 产品、材质、尺寸匹配

已完成：

- 产品候选按客户范围和以下优先级评分：存货编码、客户料号、物料名称、规格型号、规格型号加材质。
- 每行提供产品候选和材质候选，未唯一匹配显示待匹配。
- 物料名称来自物料名称栏；规格型号来自规格型号栏；存货编码映射保持。
- 材质显示清洗前导数字，例如 `045 A113B` 显示为 `A113B`。
- 材质变化触发成本重算。

结论：产品 / 材质 / 尺寸候选匹配完成。

### 2.3 多文件识别与防重复

已完成：

- 新增 `POST /api/orders/pdf-preview-batch`，支持一次上传多个 PDF。
- 单文件失败隔离，不影响同批次其他文件。
- 支持已识别、需人工确认、重复已跳过、识别失败状态。
- 文件级使用 SHA-256 `file_hash`，同批次相同文件跳过。
- 订单级使用客户、客户单号和明细签名判断；相同客户单号但明细不同标为重复候选。
- 正式保存接口再次执行重复门禁，避免重复生成正式订单。
- 前端支持逐份确认和批量保存已确认草稿。

结论：多文件识别完成；防重复识别完成。

### 2.4 成本参考

成本仅显示在：

- 新建订单明细。
- 编辑订单明细。

显示字段：

- 客户单价。
- 预估成本。
- 预估毛利。

计算口径：

- 优先使用产品成本单价。
- 产品成本缺失时，使用材质平方报价和产品/纸板尺寸公式。
- 数据或公式不足时显示“待计算”。
- 对账主表未增加成本主列。

### 2.5 订单状态、删除与未完成统计

已完成：

- 状态扩展：`completed`、`archived`、`closed`、`dead`、`cancelled`，并补齐待确认、待对账、待开票、待收款状态。
- 默认筛选为 `unfinished`。
- 已完成、已归档、已结档、已作废、已取消、死单不计入未完成数量。
- 无业务关联订单支持二次确认后完全删除，操作写日志，订单序号不回退、不复用。
- 有送货链路关联的订单禁止直接删除，只能标记死单或已结档。
- 死单、已结档、已归档、已作废必须填写备注，操作写日志。
- 界面统一使用“已结档”，未出现“已接档”。

结论：删除二次确认完成；死单 / 已结档完成；未完成订单数量统计完成。
