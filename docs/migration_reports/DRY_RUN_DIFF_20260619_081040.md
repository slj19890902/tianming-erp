## 8. 字段映射风险

1. **订单号风险**：`Orders.电脑单号` 全空；正式 `sales_orders.order_number` 必须设计稳定生成规则，建议使用带来源前缀的 `legacy_order_id`，不要使用客户单号作唯一键。
2. **客户单号非唯一**：`OrderXLs.客户单号` 大量重复且含“补单”“长期订单”等语义值，只能作为展示字段。
3. **日期精度与格式**：SQL Server 为 `datetime` 毫秒精度，legacy SQLite 为文本且使用斜杠格式、秒精度；比较和迁移时必须规范化，不能直接字符串比较。
4. **金额精度**：SQL Server 同时存在 `decimal`、`money`、`float`，SQLite legacy 使用 `REAL`；正式表迁移应使用 `Decimal` 量化到业务精度，禁止用 float 直接汇总落库。
5. **零值与负值**：订单明细存在零单价/零金额；采购明细存在 56 条负单价。正式迁移前需要明确是冲销、优惠还是脏数据。
6. **规格字段**：`规格型号` 全空，需从订单长宽高、款号、箱型等字段组合，不能直接映射为空。
7. **客户重名**：客户全称存在 2 组重复，客户关联必须使用源 `ID`/编码，不得只按名称匹配。
8. **源批次边界**：当前 legacy 抽取截止约 2026-05-30，最新权威源截至 2026-06-16；差异是连续新增批次，不是 SQLite 反向脏数据。
