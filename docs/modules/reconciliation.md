# 对账（reconciliation）

## 模块目标
- 将“回单确认数量”聚合为可核对的月度对账金额，支持月结对账和财务确认前置。

## 当前对账事实来源
- 以已回单确认且有差异原因闭环的送货记录为唯一来源。
- 对账金额按“回单确认数量 × 单价”进行计算，不以原始送货数量为准。

## 与其他模块关系
- 依赖：`delivery` 的送货单与回单状态。
- 影响：
  - 未回单确认的记录不得进入对账。
  - 对账通过后，可进入开票流程。
- 被收款阶段要求：对账完成记录可作为收款凭证链路的前提。

## 当前高风险点
- 送货回单数量与实际签收数量不一致时，金额会出现偏差。
- 部分历史退货、异常单据的回单标注可能导致误入对账。
- 对账期间状态与交付状态存在并发更新风险。

## 当前待梳理（用户确认中）
- 用户仍认为财务结算口径与现场习惯未完全一致，财务模块需要整体重构后再继续按功能点补齐。
