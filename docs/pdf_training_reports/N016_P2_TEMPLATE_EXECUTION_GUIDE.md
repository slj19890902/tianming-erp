# N016-P2 客户 PDF 模板执行说明

## 适用范围

本执行层用于尚未拥有专用解析器的新客户。天华、高泰、思迈尔继续优先使用各自的专用解析器，模板中的通用订单号、日期和明细规则不会覆盖它们。

模板只有在生命周期状态为 `active` 时才参与订单预览和训练样本重新解析；`draft` 与 `retired` 不参与路由。

## 推荐配置格式

订单号规则、日期规则和明细行规则均使用 Python 正则表达式。优先使用命名捕获组：

```text
订单号：客户单号=(?P<order_no>[^\s]+)
日期：下单日期=(?P<order_date>20\d{2}年\d{1,2}月\d{1,2}日)
```

明细行规则可以使用业务无关的组名，再由字段映射 JSON 对应到 ERP 字段：

```json
{
  "field_mapping": {
    "line_no": "row",
    "product_code": "sku",
    "product_name": "name",
    "spec": "size",
    "unit": "uom",
    "quantity": "qty",
    "unit_price": "price",
    "amount": "total",
    "delivery_date": "due"
  }
}
```

字符串表示命名捕获组；正整数表示从 1 开始的捕获组序号。旧格式 `{"product_code":1,"quantity":4}` 仍兼容。`item_columns` 继续表示表头别名，不会被误当成正则捕获组。

## 完整性与保存边界

- 明细规则命中不等于完整性自动通过。
- 当前执行层会独立提取 `合计 数量 金额`，与解析明细的数量、金额合计比较。
- 原单必须恰好存在一组独立整单合计，并且系统能从原文独立识别明细行号、与模板解析行一一对应，合计位于最后一条源明细之后；数量、金额误差都不超过 `0.01` 且所有关键字段完整，完整性才为 `passed`。
- 出现多个合计或分页小计时，系统不会猜测最后一个是整单总计，完整性保持 `unknown`。
- 原单没有可识别合计时，仍会生成草稿，但完整性保持 `unknown`、识别状态显示为 `needs_confirmation`，不能直接保存正式订单。
- 规则无效、匹配不到订单号或明细、捕获组缺失、金额或日期无法转换时，返回中文警告和 `needs_confirmation`，不会静默回退到另一客户的通用规则。

## 安全限制

- 单条正则最长 2000 字符。
- 单份待匹配文本最大 500000 字符。
- 单份订单最多允许模板命中 500 条明细。
- 单条规则最多允许 64 个捕获组。
- 用户模板正则在独立子进程中执行，单次超过 2 秒会被终止并转为人工确认，不会阻塞 ERP 后端 worker。
- 客户路由的全部模板共享 3 秒总预算；任一模板超时或执行异常时，整次路由进入人工确认，不会继续锁定另一个宽泛客户。
- 子进程返回的完整匹配与捕获组累计最多 100 万字符，超限会终止本次模板执行，避免重叠捕获制造过大内存结果。
- 嵌套重复量词、重复分支、反向引用和超大重复次数等高风险结构在模板保存时直接拒绝；历史模板运行时仍受硬超时保护。
- 零长度明细匹配会被拒绝。
- 字段映射 JSON 最大 20000 字节，必须是对象，并且只能映射白名单字段。

## 推荐训练步骤

1. 为客户建立 `draft` 模板并绑定客户。
2. 上传至少 3 份有代表性的 PDF 样本。
3. 完成人工标注和金样本复核。
4. 运行只读 dry-run，逐项核对订单号、日期、行号、编码、名称、规格、数量、单位、单价、金额和交期。
5. 只有 dry-run 达到既有激活门槛后才能激活。
6. 激活后先在订单预览中人工核对，不直接批量保存。
