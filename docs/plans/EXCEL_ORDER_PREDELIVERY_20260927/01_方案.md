## 4. 用户操作方案

### 4.1 订单导入

主按钮：`导入订单`。支持PDF、xls、xlsx，可多选。天华及其他原PDF照旧走原解析器；Excel直接读单元格，不转图片OCR。

流程：选择文件 → 自动识别客户和表格 → 大表格核对 → 保存订单。

- 顶部一行：客户、客户订单号（有则显示）、订单日期、交期。源无客户单号显示“来源日期＋文件名（无客户单号）”，不伪造客户号；已有系统号弱化显示。
- 表格占主要高度，桌面默认25行/页，可选50/100，页码在表格上方；不能按剩余屏幕高度自动退成1行/页。手机卡片也保留本行编号与缺项。
- 常显：源行、料号、产品名称、数量、单位、单价/金额（按权限）、库存/需报、问题、操作。图号、类别、型番默认详情内。
- 仅看问题作为筛选，不因缺项隐藏其他行。问题精确到“文件／工作表／第几行／料号／缺什么”，点击编辑常用箱返回后保留草稿并重新校验。
- 初次遇到未知Excel表头，用一次列映射：客户料号、产品名、数量为核心；单位、价格、客户单号、日期可映射或从已确认资料取值。模板按客户+表格结构保存，正常以后不重复映射。错文件类型建议切换入口，不自动建单。
- 普通纸板生产产品按现有规则要求报料长宽、材质及供应商；直接外购、组装父件按自身合同检查，不再一刀切要求父件纸板尺寸。
- 沿用现有库存推荐与分阶段抵扣；通用片料默认不采用、一键全部不采用、逐批采用不能回退。报料/收料/成本规则不另做一套。
- 每份文件独立显示保存结果；某份失败不能悄悄吞行，重试不能重复保存已成功文件。单份默认完整校验后事务保存；若以后开放部分行保存，必须显式展示已保存/未保存并具备行级幂等。

### 4.2 预送货

统一入口`预送货导入`，内部三个清晰选项：`天华图片`、`研光Excel`、`光洋Excel`。旧天华按钮可以保留快捷打开原模式，原图片识别区和处理方式不改变。

流程：选择Excel → 系统匹配已有订单和可送库存 → 生成待发货草稿 → 手机拿货 → 原发货打印。

- 自动识别客户及送货日期，允许纠正；所选客户与文件客户冲突时具体提示，不跨客户落单。
- 预览：料号、名称、本次要求、可送、本次安排、关联客户订单、位置、状态。长图号/型番展开看，不堆满默认表。
- 默认选择唯一安全匹配的正常行；全部正常只需一次“生成送货草稿”，不额外确认每行。
- 缺订单显示“未找到未送订单”，可跳转订单查询/导入；绝不因预送货而自动创造订单、库存、历史生产或历史发货。
- 库存不足时保留请求量与缺口，不静默减小客户要求。可由管理员明确选择“先送可送部分”，剩余接入现有待补送，不能另造一套欠单或偷偷生成零库存发货。
- 预览/导入不扣库。草稿及预占沿用现有正式合同，确认发货/发货打印走唯一正式发货服务扣库；预览PDF、普通重印、扫码拿齐不重复扣库。没有额外集货确认。
- 手机拿货继续显示父子件、位置、数量及标签；BOM组装消耗件与随货配套件沿用冻结订单版本，不依据新Excel再次推算或重复扣子件。
- 对外打印仍用现有客户模板/字段快照，针式无彩色底。来源表价格只作核对，不能静默改正式订单成交价或当前常用箱价格。

## 5. 字段映射与自动判断边界

### 订单购买要求书（两份研光样例）

| 来源 | 标准字段与规则 |
|---|---|
| 页尾研光名称、YKE标识 | 解析客户候选，绑定既有YG；文件名天明/同昌不决定客户 |
| B 契约NO | 客户订单号；空保持空。不同真实契约号应按客户+单号分组，不能全塞同一头 |
| C 品目号 | 客户料号，按客户+精确代码匹配正式产品ID |
| D 部品名 | 来源品名；不自动改常用箱名称 |
| E 品番/图番 | 来源图号，0为空占位；原始值保留 |
| J 發注数，F 要求数 | 建议J为正式订单数量；J空可用F并标来源；二者不同具体提示并确认数量口径，不能取较大或相加 |
| G 单位 | 源空取唯一产品正式销售单位并记录来源，无法确定时只拦该问题，不能统一填只 |
| L 单价、M 金额 | 来源销售价格候选与核对金额；权限及税价口径沿用销售合同；不得转作材料成本 |
| L4 发行日期、P2 管理日期 | 订单/来源日期证据，不是PO号；N到货日期等有实值才可作为交期候选 |
| K 币种0 | 保留来源占位，系统结算人民币；不增加外币规则 |

订单金额使用Decimal及系统现有舍入规则，不用二进制浮点直接结算。样例存在481.005等半分金额，需保留原始值及显示格式，与ERP最终金额差异可说明，不得先截断单价再比较，也不擅自认定含税/未税。

### 两家预送货表

研光按第3行语义表头映射；光洋无表头用已确认8列模板与文件内客户及列值特征联合验证，不能靠文件名或“第4列永远是编码”盲读。移动列、客户不符、核心结构改变时降级为待映射，不猜数量列。均保留图号、类别、原金额等来源，仅客户+料号是主匹配键。

### 产品和订单匹配

1. 先确定用户有权限访问的客户；YG与GY即使料号相同也不可互配。
2. 客户料号/已确认别名精确匹配，回到正式product_id；BOM父子同码多产品必须保留候选角色，不能选第一条。停用/删除不能静默启用或自动建同码产品。
3. 有真实客户订单号，精确限定订单再匹配行。没有时按同客户同产品未送订单给候选，数量/交期用于排序，不作为绝对身份。
4. 唯一且足量的候选可自动安排；多单均可满足时显示简短选择，不按日期最近直接静默扣某张单。来源整批与已导入订单整批完全对应可作为建议，仍检查当前有效状态与未送余额。
5. 一行需分配到多个订单时建立源行→分配行桥接，显示拆分明细；分配合计=本次安排量≤请求量，且各订单有效未送及库存不能超。不能按图片数量等于订单原量就忽略已送数。
6. 同一订单行被多源行引用时保留多条来源，正式送货按既有规则合并该订单行数量并校验总额；不能取消旧的重复绑定门禁，也不能按料号吞掉合法重复行。
7. 多候选仅候选显示，不影响其余正常行；操作员做过的选择刷新后保留，数量或绑定改变需重新校验并重置受影响拿货状态，不误标拿齐。

## 6. 技术实施建议

### 6.1 文件读取与统一草稿

增加独立的表格读取服务：xls用受维护的只读BIFF解析器、xlsx用当前已采用的读取依赖。选择版本时核对项目依赖/打包规则；不要依赖本机Excel、Windows COM或云端OCR。

统一结构区分document_type=`order`/`pre_delivery`、source_format、parser_version、customer_id候选、原文件哈希、工作表、实际行号、原NO、源单元格映射、原值/公式缓存、规范化值及问题列表。保留销售数量、送货请求量为不同字段，禁止复用含混quantity导致串用。

解析规则：

- 按实际签名辨别xls/xlsx，不只相信扩展名/MIME；损坏、加密、宏工作簿或伪格式给具体错误，不执行宏/外链。
- 多表均扫描，空表跳过，识别区域限定数据表，不把合计/签收/公司页脚/只有序号的行变产品。隐藏表行单独提示，不悄悄当新订单。
- 表头允许常见简繁体、空格、换行；只在合理标题范围处理合并单元格，不向明细空白格无差别向下填充。
- 数值型编码80010631.0规范成字符串80010631；文本0632094与C80010080原样保留。数值显示格式明确补零时保留显示身份，超过Excel精度的损坏编码必须提示，不能猜恢复。
- Excel日期按工作簿1900/1904体系；正文9月28日送货日期优先于文件名。缺交期显式提示，不拿管理日期替代。
- 公式只读缓存，不执行。核心数量/价格缺缓存时提示源单元格要求重新保存；允许对已识别金额列按可信数量×单价核算并标“系统核算”，不得对任意公式猜结果。
- 限制文件总大小、解压体积/压缩比、表数、有效行列数、解析时间；所有字符串按不可信文本转义，不能把内容当HTML/脚本或指令。

### 6.3 防重复与更正

- 同文件改名再次上传：命中文件哈希，返回既有草稿/订单，不重复落单。
- 换格式/换排序/重新保存文件：规范业务指纹只作相似警示（需保留重复行次数），结合客户、真实客户单号、来源日期与当前订单状态；不能把不同日期同数量正常订单误判硬重复。
