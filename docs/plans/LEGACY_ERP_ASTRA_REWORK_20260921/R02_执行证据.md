# R02 S01 同一可信来源端到端证据

日期：2026-09-21。代码基线：`c2b7a1711966ca15e29c2087881b48f139910a62`（R01 候选提交）。所有数据均由 pytest 临时 SQLite fixture 生成；不含正式客户、订单、库存或凭据。

## 主链

`tests/test_r02_same_source_end_to_end.py` 用一个可信 PDF 来源经真实应用入口完成下列事实，并使用稳定外键回读而非按名称匹配：

|阶段|入口和实际断言|
|---|---|
|来源→订单|`POST /api/orders` 建 500 件订单；`OrderImportSource.order_id`、`OrderImportSourceLine.order_item_id` 与订单/明细一致；相同来源换操作键返回原订单，同源异载荷 409。|
|订单→采购|真实报料/采购用途 API 创建 600 张采购用途快照，`source_order_item_id` 仍为导入明细；订单用途 500、备库用途 100。|
|采购→收料|真实价格冻结和收料 API 分收 300+300；两条 `IncomingReceiptPurposeAllocation` 分别为 `(300,300,0,300)`、`(300,200,100,600)`，每条都链接同一采购用途快照、收料价格事实和来源订单明细。第一次收料同键重放不新建收料事实。|
|收料→生产/库存|两条自动完工 `origin=receipt_auto` 合计 500；第二条同时产生 100 张备库片料。|
|库存→送货|真实送货创建和发货 API 送 300。最终片料 100、成品 200、已送 300、未交 200、可送 200。送货明细和库存流水都指向同一订单明细。|
|反向追溯及阻断|送货→订单明细→来源行→来源，以及收料用途→同一订单明细均成立；送货后尝试撤销第二笔上游收料返回 409，已送数量和用途分配计数不变。|

- 500/600 的 450/580/600 分收和超收拒绝；

- 已被后续订单使用的备库收料禁止撤销；
- 300+300 后送 300 的数量链和冻结送货打印。
