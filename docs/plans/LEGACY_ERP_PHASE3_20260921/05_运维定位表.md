# 第三阶段运维定位表

本表只列本阶段实际命中的错误和已经存在的恢复边界。它不替代管理员在备用机、实纸、手机或正式页面上的现场验收。

|症状或提示|现有证据位置|安全动作|禁止动作|
|---|---|---|---|
|保存后客户端未收到响应，无法判断订单或收料是否已提交|P01 `p01-response-loss-20260921-04/pytest.log`；`tests/test_phase3_response_loss_recovery.py`|保留原请求标识、操作者和时间；通过既有恢复查询或以原幂等键重放，核对返回同一 ID 后再继续|用新键或手工再建一张订单/收料单；以网络异常为由修改数量、库存或审计记录|
|两个操作者几乎同时提交同一收料|P04 `p04-receipt-write-contention-20260921-02/pytest.log` 的 `P02_CONCURRENCY_TRACE`；`tests/test_phase3_concurrent_transactions.py`|保留两次请求时间和业务键，读取既有事实与审计；同键重试应返回同一收料行|解除数据库锁、删除一方记录、重启正式服务，或用绕过版本的写入补录|
|调整客户范围后旧会话收到 401，或新会话读取范围受限|P03 `p03-scoped-order-auth-20260921-01/pytest.log`；`tests/test_phase3_restricted_api_auth.py`|按既有权限入口复核账户范围；旧会话失效后重新登录，再以新范围读取|复用旧 cookie、在前端隐藏菜单代替权限修复，或直接改正式数据范围|
|固定页面查询变慢或查询数异常|P04 初始失败 `p04-scale-orders-after-fix-20260921-01` 与最终 `p04-scale-orders-cache-20260921-02/scale-metrics.json`、`p04-query-regression-20260921-02/pytest.log`|记录精确筛选、页码、时间、服务日志和只读 SQL/健康证据；先在新合成隔离环境复现|提高超时、放宽 SQL 预算、切换 WAL/引擎，或对正式服务压测/故障注入|
|助手提示 NAS 不可达、空间不足、备份损坏或口令错误|`desktop_assistant/manager.py` 的备份/解密校验；`tests/desktop_assistant/test_recovery.py`|确认映射到预定 NAS，再重新执行既有备份流程；只把助手创建并解密校验成功、哈希一致的 `.tmbackup` 视为可恢复候选|回退到 C/D 本地“备份”、手工改回执/哈希、删除现有备份或泄露恢复口令|
|需要确认“有备份”还是“可恢复”|R04 `r04-desktop-assistant-full-isolated-20260921-01/result.json`；P05 `p05-assistant-recovery-20260921-01/result.json`|区分：文件存在 → 加密包完整并成功解密/哈希校验 → 空安装根恢复成功。只有后两项证明可恢复性|把 NAS 文件存在、历史截图或连通性检查写成已恢复|
|更新或迁移失败，或者启动失败|`desktop_assistant/manager.py` 的签名、兼容与启动保护；`tests/desktop_assistant/test_update_chain.py`|保留 `control/server.log`、state 和当前签名包身份；按助手拒绝信息使用确切签名桥接或已验证旧程序，必要时恢复到空根|替换签名身份、跳过迁移桥接、覆盖当前安装的数据目录，或让新旧程序同时接管同一服务|
|备用机需要接管|R04/P05 仅为合成空根证据；真实备用机仍为管理员现场项|在**全新空安装根**执行既有恢复；确认解密、附件、版本/修订、单实例服务和只读健康后，再由管理员按现场流程决定切换|在已有安装根上覆盖恢复；同时启动两台机器连接同一正式数据路径；将本表或隔离测试标为备用机已通过|

P01—P04 没有出现无法由上述证据、请求标识或助手拒绝信息定位的错误；因此未添加遥测、后台监控、定时任务、秘密字段或新的恢复写路径。
