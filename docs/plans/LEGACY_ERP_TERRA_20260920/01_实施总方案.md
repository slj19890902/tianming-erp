# 旧 ERP 优势继承：天明 ERP 分阶段实施方案

编制日期：2026-09-20。目标执行模型：用户指定 GPT-5.6 Terra。本文交付实施步骤，不在编制阶段执行功能开发、Git提交、服务更新或数据库迁移。

## 1. 目标与架构决定

目标：让文员连续录单更顺手、业务数量和历史事实更可信、打印更稳定、运行维护更省心。保留天明网页前端、统一服务端与集中数据库，借鉴旧系统的业务操作经验。现有桌面助手负责启动、诊断、更新、备份；暂不另写一套原生业务客户端。

执行原则：
1. 先保护既有能力，再定位差异，最后补最小缺口。
2. 界面只表达和收集意图，数量、客户范围、资格、幂等、事务和审计由后端强制保证。
3. 数据库保存稳定身份、来源、冻结快照和冲正关系；不复制旧表名、混合余额视图或客户端直连SQL方式。
4. 正式页不自动点击；设备和实纸由管理员人工核验。
5. 更换数据库引擎属于条件决策，不能与普通界面改进捆绑。
6. 每卡都允许以“已有符合，有证据，不改代码”结束。

## 8. 最终推荐运行形态

电脑桌面助手/浏览器 + 手机浏览器 → 同一业务API → 工厂本地集中数据库。
NAS保存已验证备份及签名包，不作为多客户端直写SQLite的共享数据库。
补本地打印能力需由实纸问题证明；不默认引入Electron/Tauri、不复制业务逻辑、不引入离线库存写入队列。
数据库引擎迁移只在T19选型证据和老板批准专项方案后另立实施卡。
