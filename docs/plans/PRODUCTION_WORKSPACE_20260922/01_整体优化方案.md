# 4 生产环节整体优化方案 V1

2026-09-22｜方案评审版｜未修改生产程序或业务数据

## 1. 结论

当前页面将生产计划、库存领料、完工登记和库存查询混在一起。最先要修复的是数量读取与领料信息，其次才是导航和视觉。建议将“4.生产”保留为顶层入口，页面标题使用“生产工作台”。

推荐一级页签顺序：**备库安排 → 待生产 → 待组套 → 成品与归位 → 生产记录**。默认打开“待生产”，记住用户上次筛选；这五个入口是工作分类，不要求每单依次经过全部页面。普通订单跳过备库安排，普通自动成品直接进入成品与归位，只有真实组装业务经过待组套。

第一批最小闭环：**修复待生产零数量 + 独立展示本单用料与位置**。其余导航调整和产出登记布局分批进行。

## 2. 现状证据与问题等级

证据分为：用户本轮截图；实时远端正式源码；本次正式数据库只读查询。其他页签按代码与规则评估，没有通过自动操作正式页面完成全流程视觉验收。

| 页面/步骤 | 当前情况与评价 | 优化优先级 |
|---|---|---|
| 1. 进入生产 | 订单主链和业务表格框架可以沿用。一级入口混合待办、库存和历史；待组套排第一，不能代表多数日常工作 | P1 |
| 2. 找到待加工任务 | 截图六款已存在有效片料预占和正数生产计划，页面却显示本次做 0，严重妨碍执行 | P0 |
| 3. 确认用料和找货 | 有印刷说明时备料摘要被条件隐藏；部分来源只在 title 悬停中显示，缺独立取料区 | P0 |
| 4. 安排备库 | “待安排 3 待安排”是一个按钮的重复文案。内容包含待来料与已到料待安排，名称不能解释范围 | P1 |
| 5. 组套 | 真实组套必须存在；已配齐不代表已组装。当前子件位置需展开，缺件、可组套数与领料量应更突出 | P1 |
| 6. 完工与去向 | 输入区和去向下拉先于计划/来源出现。“订单/多出”依赖未正确初始化的产出，容易被误当需求状态 | P0/P1 |
| 7. 找成品与归位 | 库存去向主要是备库来源及产出的投影，成品归位又单列。跨页查找、业务类型混杂 | P1 |
| 8. 查历史 | 现有记录有实际/理论、当前位置和撤销门禁，保留价值高，但不应排在当日归位待办之前 | P2 |

可见的易用性风险：关键文字偏小、同一单元格混排多种信息、低对比次要字承载重要数量、关键来源依赖鼠标悬停。保留大字模式、明确焦点、可键盘展开、颜色搭配文字；截图不能证明键盘和读屏已合规。

还发现一个现场资料问题：来源区域名称仍为“新区域（待设置）”。UI 应显示当前真实位置、地图定位和“区域名称待完善”；不能给员工编一个好看的假位置。管理员后续维护名称也不能凭本方案改写实物位置。

### 已定位的两条直接原因

1. 无供应商实收时 `_material_quantity_facts()` 返回0；库存齐套分支保存了正数 `planned_quantity`，但 `material_input_quantity` 仍为0。列表把“投入字段算出的产出”作为 `planned_output_quantity`；没有分切合同的这些预占不能走分切覆盖分支，因此列表仍得到0。前端据此初始化实际投入与实际产出，于是“本次生产/用于订单/多出”全为0。提交端还有不同的计划投入回退计算，说明列表与执行口径需要统一。
2. 商品摘要只有在 `!productionPrintingSetup(row)` 时才展示备料摘要；图中每款都有印刷说明，正好隐藏了取料信息。`productionProductTitle()` 虽拼接来源，但不能依赖悬停指导员工领料。

这里既有数量投影缺陷，也有信息布局缺陷；不能只改列标题或把输入框默认填成订单总数。

## 4. 每个现有入口如何处理

| 现有入口 | 是否保留 | 新位置与内容 |
|---|---|---|
| 待安排 3 待安排 | 保留能力，改名“备库安排” | 排第1；二级状态为待来料、待安排、保留材料/余料。数量角标只显示待处理安排数，“待来料”另标数量；取消重复文案 |
| 待生产 | 保留并设为默认 | 排第2；统一任务列表，以“全部/订单生产/备库生产”筛选，优先订单交期，不再因有备库任务就自动切到备库 |
| 待组套 | 保留 | 排第3；按订单组套、备库配套区分；显示需多少套、可组多少套、每种子件拿多少及位置、短缺多少；实物插合完成后确认一次 |
| 库存去向 | 取消独立一级按钮，保留查询能力 | 已有成品进入“成品与归位”；原料、半成品、未组套余片进入“备库安排→保留材料/余料”。统一通过来源明细追溯，不丢原记录 |

| 完工历史 | 保留，改名“生产记录” | 排第5；统一加工产出、自动形成、组套、实际数量调整及撤销的查询。当前位置和当时位置分开 |

“待安排3”和“待安排”在现有实现中不是两个独立页签，不再拆出一个新步骤。

成品与归位需要覆盖普通订单自动成品、手工加工产出、备库产出、组套成品及当前订单已预占的现成品；不能只是把现有备库库存去向改名后就声称覆盖全部成品。它复用库存事实，不另建库存账。已送完且无余货的批次仅留历史。

## 5. 待生产主表：先回答现场四个问题

主表推荐列序：

**订单/交期 ｜ 产品/加工要求 ｜ 还需做 ｜ 本单用料/在哪里拿 ｜ 当前条件 ｜ 操作**

- 订单/交期：客户单号绿底、客户简称、交期；ERP号为次要追溯信息。同一订单可视觉分组，每款仍保留稳定任务身份和独立选择。
- 产品/加工要求：编码、名称、印刷/模切/结合等冻结要求；明确“要求”和“已完成登记”。没有加工完成证据显示“未登记”，不得从名字、库存类型或产品要求猜测已完成工序。
- 还需做：最大字号显示本次计划加工数量；次行显示订单数量、现成成品覆盖、已生产覆盖与剩余缺口。计划、累计事实和本次填报各自独立。
- 本单用料：原材料、半成品、新到料分别显示；每来源显示物料名、实际尺寸/楞型、计划取用张数和完整当前货位。一批多位置或同位多批可展示分组，但追溯和操作保持真实批次。
- 当前条件：已安排待加工、部分备妥/仍缺料、用料信息待核对等。没有实际领料记录只写“计划取用/已预占”，不显示“已领料”。
- 操作：本单用料、任务单/二维码；只有既有允许手工产出的任务显示“登记产出”。自动来料路径显示“查看成品”。批量操作在选中后出现，按钮显示具体动作和可操作款数。

默认行高控制在3–4行；多来源先展示两行，再明确“另有N处”，展开本单用料后显示所有来源，不靠title或省略号隐藏必需信息。1920×1080标准模式每页约8–10款，大字约5–6款，以实测布局调整；单主滚动、固定分页口径，不出现内外双重纵向滚动。

工具栏只保留来源筛选、搜索、异常筛选、分页与刷新；标签异常维护移入明确的管理入口，有异常时再显示角标。不做占屏的大指标墙。异常数量以实时有权限任务为准，不能把历史391条当今日待办。

## 6. 本单用料展开区与仓库合并拿料

每批来源显示：**拿什么 → 在哪里 → 本单计划拿多少 → 能覆盖多少 → 还需什么加工**。

来源明细最少包含原料/半成品身份、现场名称、尺寸、楞型、当前完整位置、预占未消耗张数、已消耗张数、换算说明、对应订单/子件及冻结分切方案（如有）。已登记加工事实与本单要求并列，不用模具最大出数替代当前实际出数。

复用地图真实location_id定位；位置缺失显示“位置待核”，已移库显示当前地址，历史地址留在追溯。不得让员工自行从全仓挑替代库存；更换来源仍走管理员既有适用性/预占权限。

多款选中后提供“合并用料清单”：按真实批次及位置汇总计划取用量，再列各款分配。例如本轮六款在014号位共有134+286+120=540张的指派。成品配货另列，不混入加工用料。清单是预占的只读投影，查看、展开、打印都不扣库存。清单用于指导拿料，不冒充实际领用凭证。

纸质保留半张A4生产任务单既有规则；在空间允许时列领料简要位置/数量，完整逐批清单通过二维码或独立合并用料清单查看，不扩大成一款一整页、不暴露内部库位ID。实际打印继续留审计。

车间版显示执行所需来源、尺寸、楞型、位置和数量；材质代码、供应商、价格、成本及范围外库存不下发到无权限账号。管理员版可在明细查看。页面隐藏不能代替后端权限。

## 7. 数量必须讲清的口径

### 7.1 成品需求与材料分别记

- 订单需求、已送、当前有效成品覆盖、仍需加工均使用该产品真实单位（个/只/套等）。
- 原板用张、子件用片或各自真实单位，不能简单把多种数量相加。
- 同一订单自产成品、已送和库存抵扣不得重复计入覆盖。后台按有效来源关联去重；前端不再以“订单数量−快照”独立推演所有业务场景。
- “新采购已收0张、仓库已安排220张、计划加工220个”可以同时成立，不显示成“无料/做0”。
- 有效预占余额=预占−已消耗−已释放；盘亏/冻结/版本变化须按当前门禁重新核对。预占只是承诺，不证明实物已领。
- 已知无需再加工且满足直发规则的净片/成品按原位配货，不再次入生产或伪造完工。

### 7.2 计划、理论、实际分开

计划加工量来自剩余订单需求与本次已分配用料；理论产出来自冻结的来源换算；实际产出仅来自真实登记。界面不得在第一次打开时把计划数字描述成“已完成”。

普通单料示例：实际投入×本次出片数÷每成品用片数，按既定取整规则形成理论数量。多组件按冻结配比的瓶颈算可成套数，不能把子件数求和当套数。截图六款恰好1:1，不能作为通用算法。

### 7.3 登记产出时才展示分配

将现有“本次生产”和“订单/多出”移到行内登记区或弹层，使用明确名称：实际投入、合格产出、本次补给订单、超出订单成品、成品位置。结果预览由后端统一计算，保存再次校验。

既有允许自动成品的普通收料保持自动流转；只在库存加工、备库加工和真实组套等适用路径登记一次事实。不增加“开始生产、印刷完成、模切完成”等日常点选。

原料未用整张、可复用边料、报废与合格超产分别处理，不能统称“多出”。第一批不新增逐批实际领退料账，也不开放当前不支持的分切拆批完工。现有分切合同要求整批确认时明确提示；若后续要改为部分用料/余料退回，另做数量与成本专项闭环。

选择“成品去向”只编辑草稿，不应该隐式触发不可见提交；以清晰的“登记产出并入库”按钮提交一次，普通操作不额外弹二次确认。真实超理论、撤销等保留现有一次确认规则。

## 8. 其他四个页面的内容

### 备库安排

待来料列预计到达、产品/物料、待收数和来源单；待安排列真实已到数量、原位置及可安排量。管理员可选择部分数量转生产，也可保留原料/半成品或存放；默认不把整仓可用量都当本次生产任务。已有一键转待生产能力保留，提交前展示实际安排范围，后端仍检查版本和数量。已预占给订单的材料不会再出现在可自由安排量中。

保留材料/余料页保留原料、半成品、子件原身份和位置；未组套配比参考必须标明“尚未组装”。存放只移动批次，不新增库存。

### 待组套

主行显示父件/订单、需组套数、当前可组套数和缺件提示。展开按子件列每套用量、本次需用、已安排、缺口和位置。缺件任务仍可见；实物完成多少套就确认多少套，事务扣子件、生成父件成品、继承成本。随货配套不能误当组装消耗；已组成套的库存不再次领取子件。

### 成品与归位

主行显示产品、当前成品总量、本单预占、自由可用、待送关联、当前位置及待归位状态。待归位是当前库存投影，不从历史完工条数推算。未归位逻辑位置和地图实位明确区分；真实待送库存按既有规则可送，不强迫先搬上楼。归位前校验位置/容量/版本；同位汇总只按已批准的同身份条件，展开仍对应真实批次。

### 生产记录

按实际发生时间倒序，筛选客户单号、编码、时间、记录类型、操作者。显示本次投入/产出、订单分配/超产、原来源及当前库存；自动形成记录明确标识，不冒充员工确认。撤销/改量收在管理操作内，仍按已送、预占、下游使用和权限门禁阻止非法操作。

## 9. 实施顺序与验收

| 阶段 | 交付闭环 | 必须验证 |
|---|---|---|
| A：数量与用料 | 统一列表/提交数量口径；印刷说明不遮挡取料；原料与半成品明确区分 | 截图六款；成品+片料混合抵扣；多货位；无采购全库存；有采购但部分缺料；未知位置/换算显式报错 |
| B：导航与查询 | 五个入口；待生产默认；订单/备库同一工作台；库存去向按身份归并 | 旧入口深链接兼容、分页/筛选/角标一致；权限范围；不能遗漏普通自动成品与历史余货 |
| C：产出/组套/归位 UI | 独立产出登记区、准确组套清单、当前位置与待归位待办 | 幂等、旧版本拒绝、事务回滚、成本继承、已有下游禁止撤销、选去向不隐式提交 |
| D：合并清单与工厂大字 | 按批次/位置汇总，稳定任务二维码，标准/大字版 | 同批跨订单不重复取；合计不超过各单有效预占；半张A4；1920×1080；手机只读任务详情一致 |

实现优先复用现有表与接口，首先只改读模型和展示；“无迁移”须开发阶段证实后再结论。新增实际领料/退料若确需新事实，单独设计，不能以CSS或临时字段冒充能力。

开发从届时实时正式基线建独立工作树，保护当前未提交文档。定向回归覆盖现有 `test_sheet_cut_production.py`、备库flow/groups/disposition、成品归位以及库存预占/订单任务相关测试，并补充本次零值失败用例。开发验证用隔离副本；正式发布沿用备份、迁移链、回滚和健康门禁。正式页面交管理员人工验收，不自动点击。

管理员最终只需三步验收：

1. 打开这张客户订单的六款，逐款核对待加工数量与本单用料；印刷说明和两处来源能同时看到。
2. 查看一笔备库与一笔组套，确认原料、半成品、成套成品和缺件各自清楚，查看/打印不改库存。
3. 在真实业务发生时登记产出或归位，核对一次提交、一份流水、正确位置和完整追溯；不为验收制造正式模拟数据。
