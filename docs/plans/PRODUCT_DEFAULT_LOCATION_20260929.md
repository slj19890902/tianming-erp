## 任务与验收目标

来源：老板 2026-09-29 要求货架添加货物保存后，以该位置作为此常用箱后续默认位置，除非人工修改；先制定完整方案，再交 Sol 或 Terra 执行。

从实时正式分支 `08af5dc999dcc10b1bb68387f2296e6f99ebd787` 建立独立分支 `codex/product-default-location-20260929`。Astra 负责方案、复核、发布；Sol 负责允许范围内的实现和定向回归。

可观察结果：常用箱尚无默认配置时，管理员明确向正式货架添加成品并保存成功，即记住本次真实层格；已有其他库存位置不再妨碍首次记住。以后在别处添加、库存清零都不会覆盖；管理员在常用箱编辑内可查看、修改和取消。

## 现状与原因

已有 `ProductStoragePreference`，以产品 ID 为主键，保存正式区域、稳定货位 ID 及版本。已有常用箱编辑 GET/PUT、客户范围、管理员权限、版本检查、幂等和审计。空目的地配置是明确取消，不能与从未配置混同。

`receipt_putaway.remember_stocktake` 目前只在该产品全部正库存都处于当前货位时首次记忆，导致存在别处库存的常用箱，当前明确的新增操作无法记住。新增批次执行末尾已经调用该服务，同批按提交顺序执行。

## 规则

1. 初次成功添加的正式成品货架层格是默认位置；已有库存不用于倒推或阻止这次选择。同批同产品多格时，以第一条合格新增结果为准。手机同一添加入口选择待归位既有库存时，成功首次归位也使用该规则，不额外增加库存；普通已定位库存移货不自动新设默认。
2. 任何已有默认配置均保留，包括仅指定区域、明确取消及人工改过的位置。自动记忆不得覆盖旧排他固定货架绑定 `ShelfBinding`。
3. 当前添加仍写入本次明确选择的位置；默认值只供后续既有自动收料/成品入位规则使用，不能改变此次目标或搬动旧库存。
4. 人工修改沿用现有版本、权限、客户范围和幂等检查。取消后禁止未来自动恢复；可再人工配置。
5. 仅正式有效、已发布地图的成品货架；半成品、原料和地面临时位置不自动成为常用箱默认层格。按真实产品 ID 隔离，BOM、共享模具和相同编码不传播默认位置。
6. 位置停用或失效时保留原配置，并沿用既有待归位与异常提示；不自行另选位置并重写默认。未启用新收料流程的旧安装契约保持。
7. 默认位置和库存新增在同一事务中提交；保存失败不留默认位置或审计残留。同产品并发由现有产品锁及首次创建保护控制。
8. 不批量回填历史默认位置，不修改历史库存、成本、订单、客户权限、位置身份或数量事实；无新增表、无数据库迁移。

## 页面

常用箱编辑直接显示当前默认位置状态，不以打开隐藏折叠为读取前提。保留楼层、区域、货架层格选择及修改、取消入口；明确区别未设置、已设置和已取消自动记忆。辅助解释使用可点开的提示，显示“只影响后续收料及自动成品入位，不移动现有库存”。
