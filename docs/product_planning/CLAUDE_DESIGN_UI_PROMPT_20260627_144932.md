# 可直接交给 Claude Design 的 UI 设计提示词

你是资深工业软件产品设计师。请为“纸箱厂 ERP / 天明包装开票系统”设计一套清晰、稳定、适合工厂长期使用的桌面端与手机端 UI。先输出信息架构、设计系统和关键页面高保真方案，不写后端代码。

## 1. 项目真实现状

这是三级纸箱厂 ERP，核心流程是：

报价 → 下单 → 报料 → 来料 → 生产/待送货 → 送货 → 回单 → 对账 → 开票 → 收款。

当前正式技术形态：

- FastAPI + SQLAlchemy + Alembic + SQLite
- 正式前端为 Vue 3 单文件静态页面
- 已有登录/RBAC、客户、常用箱、材质、订单、OCR、报料、来料、送货、回单、对账、开票、收款、备份
- 已有桌面端和独立手机来料页
- 纸板长宽、压线、材质、图纸、主系统单号/明细单号已存在

当前最重要的限制：

- 不能破坏现有订单、报料、来料、送货、回单、对账链路
- 不改历史迁移原始层
- 不把系统设计成大型 SAP、MES、WMS 或完整财务软件
- 仓库是后续版本，当前先预留入口和结构
- 库存推荐只能由系统推荐，必须人工确认后才扣减

当前 UI 问题：

- 桌面端基础字号只有约 13px，小按钮约 26–32px
- 表格密集，小字和浅灰字较多
- 没有标准/大字模式
- 页面样式不统一
- 订单、常用箱、系统设置弹窗信息过密
- 手机来料已有大按钮，但默认卡片字段仍偏多
- 正式页面依赖公网 CDN，视觉设计需考虑离线构建后的本地资源

## 2. 设计目标

目标用户：

- 老板/管理员
- 销售/跟单
- 财务
- 车间
- 仓库/收料
- 送货人员
- 约 60 岁、老花眼或不熟悉复杂软件的使用者

风格：

- 工厂业务软件
- 稳重、清晰、高对比
- 信息密度适中
- 不做互联网营销页
- 不做科技大屏、暗黑风、花哨渐变、玻璃拟态
- 不依赖图标表达关键状态，图标旁必须有文字

请同时设计两种显示密度：

### 标准模式

- 正文 14–16px
- 表格内容至少 14px
- 按钮高度至少 36–40px
- 表格行高 44–48px

### 大字模式 / 长辈友好模式

- 主正文 16px 起
- 表格内容 16–18px
- 关键数字 20–24px
- 桌面按钮至少 44px
- 手机按钮至少 52px
- 输入框至少 46px
- 表格行高 54–60px
- 允许用户放大页面
- 禁止低对比浅灰小字

## 3. 全局设计系统

颜色语义固定：

- 客户信息：蓝色系
- 草稿/未确认：蓝灰
- 待处理/待报料/待收料/待回单：橙色
- 进行中/已报料/生产中：蓝色
- 已完成/已收货/已送货/已收款：绿色
- 财务/对账/开票：紫色或深蓝
- 片料库存：青色
- 成品库存：绿色
- 人工确认字段：黄色背景或黄色描边
- 异常/缺料/超长/数量不一致：红色或高对比黄色
- 危险操作：红色，必须二次确认

要求：

- 状态标签必须有文字
- 同一状态跨模块保持同色
- 文本对比度满足 WCAG AA
- 表格默认白底，表头浅灰或浅蓝
- 关键业务数字右对齐
- 搜索和筛选集中成卡片，不散落
- 危险按钮不常驻主视觉，放入“更多”并二次确认
- 弹窗不要套弹窗；复杂表单优先右侧抽屉或整页步骤流
- 每个关键操作必须有成功、失败、加载、空状态

## 4. 导航与角色

桌面端左侧导航，顶部显示当前账号、角色、大字模式开关和刷新。

角色：

- 管理员：全部功能
- 财务：订单查询、客户查询、回单、对账、开票、收款
- 销售/跟单：客户、常用箱、订单、报料、送货
- 车间：订单只读、来料、生产、送货只读
- 仓库：来料、库存、扫码、损耗
- 送货：送货单、签收状态
- 只读：查询和导出

当前系统只有管理员、财务、业务、车间四角色。仓库、送货、只读角色标为后续版本，并注明需要后端和数据库配合。

## 5. 页面设计

## A. 首页 / 工作台

显示：

- 今日新增订单
- 今日待报料
- 今日待收料
- 今日待生产
- 今日待送货
- 待回单
- 本月待对账
- 待开票
- 待收款
- 库存超期提醒（后续）
- 异常提醒

快捷入口：

- 新建订单
- OCR 导入订单
- 报料
- 来料入库
- 生成送货单
- 月结对账

不要做复杂图表大屏。老板应在 10 秒内看懂“今天还要处理什么”。

## B. 订单管理

采用“客户订单组列表”：

- 客户名称
- 客户单号
- 下单日期
- 交期
- 子单数
- 总数量
- 已送/未送
- 总金额（按权限）
- 状态
- 展开
- 操作

主系统单号默认弱化。展开后显示：

- 明细系统单号
- 主系统单号
- 存货编码
- 产品名称
- 规格
- 材质
- 纸板长宽
- 数量
- 已送
- 单价/成本/毛利（按权限）
- 状态
- 图纸

支持筛选：

- 日常订单
- 未完成
- 已完成
- 已归档
- 已结档
- 死单
- 已作废

异常提示：

- 数量不足/超送
- 缺料
- 未匹配产品
- 2500mm 超长
- 库存可抵扣（后续）

## C. 新建订单 / 编辑订单

使用右侧宽抽屉或独立步骤页：

1. 客户与客户单号
2. 订单日期和交期
3. 产品明细
4. 成本参考和校验
5. 保存确认

明细字段：

- 存货编码
- 产品名称
- 规格型号
- 材质
- 层数/楞型
- 纸板长宽
- 压线尺寸
- 数量
- 客户单价
- 销售金额
- 预估纸板成本
- 预估毛利
- 图纸
- 生产备注

交互：

- 未选客户前禁用产品选择
- 选择客户后只显示该客户常用箱
- 自动带出常用箱字段
- 人工修改项黄色标记
- 超过 2500mm 时显示高对比警告，不禁止保存
- 显示“建议检查双拼”，但必须人工确认
- 库存推荐只展示，不自动扣减

## D. OCR 导入订单

步骤：

上传多个文件 → 识别 → 客户匹配 → 明细匹配 → 人工确认 → 保存。

每个文件状态：

- 识别中
- 已识别
- 需人工确认
- 重复已跳过
- 识别失败

字段状态：

- 绿色：高置信自动匹配
- 黄色：需要人工确认
- 红色：缺失或冲突

必须展示：

- 原文件名
- 客户候选
- 客户单号
- 存货编码
- 物料名称
- 规格型号
- 数量
- 产品候选
- 材质候选
- 重复原因

只有所有必填项确认后才能写正式订单。手动换客户不得清空识别草稿。

## E. 报料页面

显示：

- 客户/订单/产品
- 原始订单数量
- 纸板长宽
- 压线尺寸
- 材质/楞型
- 供应商
- 推荐库存抵扣
- 人工确认抵扣
- 最终报料数量
- 特殊处理：无/大做小/双拼/多拼
- 超长提醒
- 风险提示

库存推荐（后续）必须显示来源、库位、二维码、可用数量、风险，不允许自动扣减。

## F. 送货管理

统一状态时间轴：

草稿 → 已保存待发货 → 已确认发货 → 已签收 → 已对账。

按钮规则：

- 草稿：编辑、删除、保存
- 已保存待发货：编辑、删除、确认发货
- 已确认发货：查看、补打、取消发货
- 已签收：管理员处理异常
- 已对账：锁定，管理员反审核后才可逆转

取消发货必须显示影响：

- 将恢复哪些订单的待送数量
- 是否存在回单
- 是否已对账
- 是否允许操作

送货单详情：

- 客户、客户单号、产品、规格、材质、数量、单位、日期
- 收货人、地址、车号、备注
- 发货、回单、对账状态
- 公司抬头和打印预览

## G. 对账 / 开票 / 收款

以客户和月份为主：

- 客户
- 月份
- 日期范围
- 对账单号
- 应收
- 已开票
- 已收款
- 未收
- 状态

明细：

- 送货日期
- 送货单号
- 客户单号
- 产品
- 规格
- 材质
- 实收数量
- 单价
- 金额
- 备注
- 开票状态
- 对账状态

导出按钮明确显示文件名预览：

`客户缩写 + 月份 + 对账单.xlsx`

成本利润分析不要塞进对账页，后续单独页面。

## H. 客户管理

包含：

- 客户编号/缩写/名称
- 联系人/电话/地址
- 账期/税率
- 开票信息
- 默认送货方式
- 状态
- 历史订单
- 常用产品

客户缩写用于对账文件名，可配置、可预览。

## I. 产品 / 常用箱管理

列表必须可快速看到：

- 客户
- 料号
- 产品名称
- 规格
- 材质
- 纸板长宽
- 压线
- 层数/楞型
- 单拼/双拼
- 净片/毛片
- 默认供应商
- 单价
- 状态

当前已存在纸板长宽、压线、材质、图纸和价格字段。单拼/双拼、默认供应商作为结构化字段仍需后端配合。

## J. 材质管理

显示：

- 材质代码
- 层数
- 楞型
- 面纸/芯纸/里纸
- 克重组合
- 平方价
- 供应商
- 生效日期
- 替代风险

提供同克重多供应商对比，但明确“仅供参考，人工确认”。

## K. 仓库管理（后续版本）

一级导航：

- 片料库存
- 成品库存
- 库位
- 栈板
- 库存流水
- 损耗记录
- 库龄提醒

列表关键字段：

- 二维码
- 库位/栈板
- 客户来源
- 关联产品/订单
- 规格/材质/纸板长宽/压线
- 总数量/可用/占用/损耗
- 入库时间/库龄/最近使用
- 状态

库龄：

- 超过 1 年：黄
- 超过 1.5 年：橙
- 超过 2 年：红

## L. 手机端收料

默认列表只显示：

- 纸板尺寸（最醒目）
- 数量
- 供应商
- 到货日期/今日
- 大号“收货”按钮

点击展开：

- 客户
- 客户单号
- 产品
- 材质
- 纸板长宽
- 压线
- 图纸/压线图
- 备注
- 供应商送货单号
- 实收数量
- 异常说明

手机端必须允许缩放，按钮至少 52px，数量输入大号，异常按钮高对比。

## M. 二维码扫码页（后续版本）

扫码对象：

- 库位
- 栈板
- 片料
- 成品
- 刀模货架区域
- 印刷版货架区域

扫码后可：

- 查看
- 取用
- 退回未使用
- 损耗
- 变更库位
- 添加备注

数量变更必须显示变更前后和关联订单，并提示会写操作日志。

## N. 权限 / 登录

- 登录页简单，大输入框
- 不展示默认密码
- 角色菜单清晰
- 未授权页面不显示入口
- 越权操作显示中文说明
- 管理员危险操作集中在系统设置

## 6. 仓库推荐规则的 UI 表达

推荐排序：

1. 同客户、同料号、同尺寸、同材质
2. 同客户、同料号、尺寸略大、同材质
3. 同客户、同材质、尺寸接近
4. 通用库存、同材质、尺寸接近
5. 其它可用但有风险

每个候选卡片必须显示：

- 推荐等级
- 可用数量
- 尺寸余量
- 预计浪费
- 库龄
- 材质风险
- 单拼/双拼建议
- 人工确认按钮

强约束：

- 长宽不足不可推荐为可用
- 单瓦/双瓦不能互替
- 瓦型不可错误替代
- 白卡面纸不可用普通牛皮替代
- 克重接近只作为风险候选

## 7. Claude Design 输出要求

请输出：

1. 信息架构和角色导航
2. 设计 token：字号、间距、按钮、表格、颜色、状态
3. 标准模式和大字模式对比
4. 桌面 1440×900 关键页面
5. 手机 390×844 来料和扫码页面
6. 每页正常、空、加载、错误、无权限状态
7. 送货单状态流图
8. 库存推荐人工确认流程
9. 关键组件清单
10. 标注哪些为当前已有、哪些需后端配合、哪些为未来仓库版本

不要生成无法操作的装饰性大屏，不要把所有字段同时平铺。
