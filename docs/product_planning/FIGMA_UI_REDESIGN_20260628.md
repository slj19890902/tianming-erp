## 二、核心问题

### P0：手机来料页面不可用

- 390px 宽度下标题、提示、字段和按钮被挤成逐字纵排。
- 已登录并有真实待收料数据时仍然复现。
- 页面 viewport 禁止用户缩放，与老花眼用户需要放大的目标冲突。
- 纸板尺寸、数量和“确认入库”没有形成稳定的第一操作层。

### P1：桌面端字号和点击区域偏小

- 表格、辅助文字、筛选按钮和状态标签普遍偏小。
- 大量低对比灰字不利于 60 岁左右用户长期使用。
- 缺少标准模式和大字模式。

### P1：宽表格依赖横向滚动

- 桌面仓库来料、送货回单和新建订单在 1440px 下仍需要横向滚动。
- 最重要的状态和操作经常被推到屏幕右侧。
- 新建订单将大量字段横向铺成一行，不符合录入顺序。

### P1：操作安全层级不足

- 客户停用、材质删除、取消发货等危险动作长期显示在行内。
- 普通操作、关键操作和危险操作视觉权重接近。
- 状态变化缺少影响范围说明。

### P2：状态和模块颜色不统一

- 页面主要依赖蓝、绿胶囊按钮，业务类型区分不足。
- 客户、待处理、已完成、财务、人工确认、异常等语义没有形成固定系统。

## 三、确定的设计方向

风格：浅色、高对比、稳重工业软件；不使用暗黑、渐变、玻璃拟态和装饰性大屏。

字体：`Noto Sans SC`，实现时回退到 `"Microsoft YaHei", "PingFang SC", sans-serif`。

### 标准模式

- 正文：15px
- 表格：15px
- 辅助文字：14px
- 页面标题：26px
- 关键数字：22px
- 按钮高度：40px
- 输入框高度：42px
- 表格行高：48px

### 大字模式

- 正文：17px
- 表格：17px
- 辅助文字：16px
- 页面标题：30px
- 关键数字：24px
- 按钮高度：46px
- 输入框高度：48px
- 表格行高：58px
- 手机主要按钮：56px

### 固定颜色语义

- 客户信息：`#1D4ED8`
- 待处理：`#C2410C`
- 进行中：`#0369A1`
- 已完成：`#15803D`
- 财务状态：`#6D28D9`
- 人工确认：`#A16207`，配浅黄色背景
- 异常 / 危险：`#B91C1C`
- 草稿 / 未确认：`#475569`
- 片料库存：`#0F766E`
- 成品库存：`#166534`

状态标签必须同时显示文字，不允许只使用颜色。

## 五、关键页面重设计

### 首页工作台

- 第一行只显示今日和本月最关键的待办。
- 卡片包括：待报料、待收料、待生产、待送货、待回单、待对账、待开票、待收款。
- 金额和数量分别右对齐。
- 异常提醒独立使用红色边框，不做大屏图表。

### 订单管理

- 默认按客户 + 客户单号分组。
- 第一层只显示客户、客户单号、交期、子单数、总量、已送 / 未送、金额和状态。
- 展开后显示产品、规格、材质、纸板尺寸、数量、成本和毛利。
- 列表固定左侧客户列和右侧主操作列。
- 危险操作放入“更多”菜单。

### 新建订单

改为宽抽屉或独立步骤页：

1. 客户与客户单号
2. 产品明细
3. 报料 / 纸板尺寸
4. 成本与异常校验
5. 保存确认

人工修改字段使用浅黄色背景。超过 2500mm、数量异常和产品未匹配使用高对比警告。

### 送货与回单

- 用状态时间轴区分待发货、已发货、待回单、回单已确认和已对账。
- 列表首屏保留送货单号、客户、日期、数量、发货状态、回单状态和主操作。
- 明细放入展开区或详情抽屉。
- 取消发货必须展示会恢复的订单数量和是否存在回单 / 对账。

### 对账、开票与收款

- 以客户和月份为主筛选。
- 顶部显示应收、已开票、已收款、未收四个金额。
- 对账单、发票、收款记录分为三个页签。
- 生成对账单前显示实收数量和金额合计。

### 手机来料

默认卡片只显示：

- 纸板尺寸
- 数量
- 供应商
- 到货日期
- 56px 高“确认收货”按钮

客户、产品、材质、压线、图纸和备注放入展开详情。

必须允许用户缩放，不得设置 `user-scalable=no`。
