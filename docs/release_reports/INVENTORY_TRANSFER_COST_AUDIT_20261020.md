# v0.22.690 库存移库来源与成本继承修复

状态：开发验证，待正式技术发布。

用户要求检查其他正常入库库存的同类问题，修复后直接发布。工作区为 inventory-transfer-cost-audit-20261020，基于实时正式 v689 源码821fe81b及报告c36d838d；远端factory-current-baseline仍为旧b9a077bc，未作为新基线。

## 根因与修复

- 新鲜只读快照中760个有实物批次，成本均可核验；918、1424、1470三个历史组套批次缺冻结时间但原消耗和成本依据存在，不回填历史时间。
- 自动补库、裁切完工、实际规格来料的成本核验将输出/收料外键与当前批次ID直接比较。部分移库生成子批次后，原外键仍正确指向首批，导致来源误判。以真实移库边和双边数量流水追到原批次，并验证原实物、日期、成本快照一致。自动补库投入任务继续核对原产出ID。
- 实际规格片料成本汇总的标量投影缺少半成品材质ID及纸板长宽，补齐所需只读字段。
- 55个盘点导入实存批次拆分误复用首次导入身份，触发数据库一次入库触发器和唯一索引。拆分使用inventory_onboarding_transfer且保留原导入行ID与真实移库记录；原首次入库保护保持不变，新增拆分必须在提交前通过完整流水及快照核验。整批移动保留原批次。
- 既有v689组套移库核验抽成共用服务，加入片料移库流水键及转移数量守恒核对；不按产品编码特判，不伪造冻结成本，不修改权限。

## 验证与边界

- 独立装载v689原成本实现，三个真实收料/生产夹具均复现成本失败；使用修复后执行部分、连续拆分、整批移动、同键重放及成本列表验证。
- 新鲜正式只读快照使用受管UAT副本和同时捕获的正式地图进行逐批移库演练；所有演练事务回滚，正式服务未写入业务事实。
- 伪造移库边、丢失流水、改成本、改实物身份、循环来源和盘点来源拆分都不能通过；新组套仍必须具有冻结时间。
- 保留唯一Alembic head et1019fl，无结构迁移；不改写历史成本、日期、库存、预占、单据或产品资料。
- 定向回归57项通过，1项v689以前已确认的subkit旧单位夹具失败排除；首轮因PATH无node导致JS语法检查环境失败，补齐既有Node运行时后整组57项通过。编译、diff-check及唯一head通过。
- 751个可拆分实存批次在隔离副本逐批演练全部通过（包含未归位正式专用入口）；首轮旧实现648通过、2个自动生产拆分成本失败、55个导入拆分失败，另46个因演练未选择专用归位入口被位置门禁拒绝，使用正确入口后通过。9个单件批次完成成本读取检查。
- 受管测试副本因无权确认系统服务进程退出而按原清理门禁保留，结果和日志已独立保存。未运行全量，不自动点击正式页面。
