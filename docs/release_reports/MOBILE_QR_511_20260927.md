# v0.22.511 二维码标签手机化与旧码兼容

状态：v0.22.511 已正式发布，待管理员手机、微信和实体纸张抽查。

## 交付范围

- 统一手机二维码 origin：优先 `ERP_MOBILE_QR_ORIGIN`，兼容既有 `ERP_SHELF_LABEL_ORIGIN`，最后使用正式 `ERP_BROWSER_URL`；生成端不再读取请求 Host 或猜测网卡 IP。
- 新整架码使用 `/scan/rack?floor=...&rack_id=...`，按正式 `map_rack_id` 打开手机仓库地图并展开对应货架。
- 新货位、货位产品、产品、库存批次、模具、生产任务、来料和天华拿货码分别进入 `/q`、`/P`、`/I`、`/M`、手机生产、手机来料和原限时拿货页；对象语义不合并。
- `/I/{lot_id}` 在权限与客户范围内解析批次当前货位，地图显示实物、预占/订单占用、单位和当前分布；移库继续调用既有版本、事务、幂等和审计接口。
- 登录返回目标使用站内路径白名单，保留对象查询参数和片段；禁止协议相对路径、外域和带账号口令的 URL。
- 扫码 GET 只读。本次没有数据库迁移，不修改正式库存、订单、货位、客户范围、权限或历史打印事实。

## 新旧码支持矩阵

| 对象 | 新码 | 已打印旧码 | 兼容结果 |
|---|---|---|---|
| 整架 | `/scan/rack?floor=&rack_id=` | `/warehouse.html?floor=&rack_id=` | 手机/微信请求 302 到新入口；电脑地图保持原页；内置扫码器可从受信任旧主机本地提取身份 |
| 货位/货位产品 | `/q/{location_id}[/{product_hash}]` | 同路径；或 `/warehouse.html?tab=locations&location_id=` | 继续进入手机货位页；旧桌面路径只在移动端转换并保留合法产品身份 |
| 产品 | `/P/{product_id}` | 同路径 | 继续进入手机产品实时页，权限和客户范围保持 |
| 库存批次 | `/I/{lot_id}` | `/static/finished-goods-label.html?lot_id=&version=&view=validate` | 旧打印页在手机端转到当前批次地图；桌面仍可按历史版本校验和补印 |
| 模具 | `/M/{mold_id}` | 同路径；旧 `/mobile/mold-lookup?mold_id=` | 新旧均进入手机模具页；内置扫码兼容旧静态别名 |
| 生产任务 | `/mobile/?mobile_page=production&task_id=#production` | `/mobile/?task_id=#production` | 旧路径仍可用；内置扫码规范化并保留任务号；登录后返回原任务 |
| 来料入口 | `/mobile/?mobile_page=incoming#incoming` | `/incoming.html` | 手机/微信旧入口转到手机来料；`embedded=1` 与电脑来料页保持 |
| 天华拿货 | `/mobile/tianhua-pick?token=` | 同路径 | origin 统一；令牌范围和有效期不变，过期码不恢复授权 |
| 固定货架拿货 | `/sp/{location}/{product}/{version}/{address_version}` | 同路径 | origin 统一，原版本与位置校验保持 |

## 无法自动兼容与补印规则

以下纸码不能由应用在微信/系统相机外部自动修复，因为请求到不了当前服务或缺少可信对象身份：

1. 已停用且 DNS、证书、端口或路由均无法接管的旧主机。可先用 ERP“扫旧标签”识别白名单内的 `tianmingerp0909.share.zrok.io`、`192.168.3.80`、`172.16.1.26`；需要微信直接扫码时补印。
2. 不属于上述受信任主机、路径不在支持矩阵、参数被裁切/污损或 `rack_id`、对象编号无效的码。内置扫码拒绝跳转，必须按当前对象重新打印。
3. 已删除、停用、未发布到地图或已失去当前客户访问权的对象。不得猜测替代对象；先由管理员核对台账，再决定恢复登记或补印。
4. 已过期的天华拿货 token。不得延长期限；由有权限人员从当前预送货草稿重新生成。

正式库发布前只读核对结果：`warehouse_rack_level_label_print_jobs=0`，正式库没有记录v509/v510仓库地图临时打印出的整架/分格纸张及其原始URL，因此无法从数据库准确枚举现场每一张旧货架纸码；不得虚构补印数量。模具打印任务84个/221件、生产包装标签任务29个/31个任务快照均保留，且其稳定 `/M`、`/P` 对象路径可兼容，无需批量重打。正式文本快照中没有保存 ERP 二维码 URL。

据此，当前明确补印清单为：现场扫码失败且原主机不可达、并且 ERP“扫旧标签”也无法识别的货架/货位/批次标签；污损或参数残缺标签；对象已经重建而旧稳定ID不存在的标签；需要微信直接扫码但旧主机已停用的标签；过期天华拿货码则从当前草稿重新生成，不作为永久标签批量补印。管理员按现场失败标签逐张补印，系统不改写历史打印记录。

## 管理员最短验收

1. 仓库地图选择一个货架，点击“打印货架标签”，标签内容选“货架编号＋二维码（不含层格）”，40×80、100%、无边距试打一张。
2. 手机扫描该新码，再扫描一张v510旧整架码；两次都应进入同一真实货架。退出登录后重扫，登录后仍返回该货架。
3. 抽查一张旧货位、产品、模具和成品批次码；批次应显示当前货位，移动权限按账号显示。
4. 用 ERP“扫旧标签”读取一张旧主机码；再用无仓库权限账号扫描，确认不能看到库存。
