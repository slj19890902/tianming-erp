# 位置清单订单导入与提前备货单

状态：开发验证通过，尚未正式发布。

## 范围与实现

- 用户确认 L 为单价、M 为金额，并授权按已讨论方案优化订单导入。工作区 `order-early-pick-20261020`，分支 `codex/order-early-pick-20261020`，实际源码基线 v692/ad44d7a3；过期远端 factory-current-baseline 仅用于建分支，已快进到实际正式源码。
- 新模板 `yg_gy_location_order_v1`：C 位置、D 编码、E 完整需求、L 单价、M 金额；J/K 保存为来源参考。H 若提供则与 D 校验，不是必填。无缓存的 K/M 按已确认的 J−E、E×L 补算，已有金额与数量×单价不一致则阻止。隐藏和未识别表给出提示。
- 上传区可选研光/光洋和要求交期；文件客户冲突拒绝。无客户 PO 可留空，不伪造编号；该模板保存必须填写交期。按当前客户精确匹配产品，保留重复编码的独立原行。
- 来源位置与参考量随原有签名保存到来源行 JSON；重新匹配沿用可信原始字段。文件哈希防重复及原保存恢复保持；再次上传同一文件显示原订单，可直接打开其备货单。
- 新只读接口 `/api/orders/{order_id}/early-pick` 和独立打印页。导入保存后、单张/整组订单详情有入口。打印/刷新仅查询，不建送货、不预占、不扣库；需要 orders.view 和客户范围权限。
- 使用既有订单准备度、实际预占来源及合格成品候选；整批避免重复计算同一可用批次。按冻结单位处理、排除材料和未组套子件；正式生产/报料后不静默新增库存抵扣。只计指定有效位置，其他位置只提醒。空位置、“板”、未唯一匹配、失效位置显示待核对，不猜测位置分解。
- 缺货和未生产行保留；已送数量从待备中扣除，关闭明细不再备货，作废/关闭订单拒绝。实拿手写，无价格输出。原发货流程保持。

## 发布后最短人工验收

1. 订单 → 导入客户订单，选择研光和要求交期 2026-10-20，上传原文件；核对 45 行、第一行需求 450/单价 3.808 和来源位置。
2. 按原流程核对产品及库存采用并保存，点击打印提前备货单；核对缺货/未生产行、C 列位置、待核对提示。关闭打印页后原订单仍在。
3. 在订单详情重新打开备货单；再次上传同一文件应提示原订单，不建立第二张订单。检查打印不增加送货记录或改变库存。
