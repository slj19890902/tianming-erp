## 交付内容与员工操作

- 左侧报料直达报料页；生产顶部按待加工、子件与组套、已入库、加工记录组织。仅生产权限账号保留生产入口。
- 导入库存余量使用同客户整批拟抵扣后的可用数量，最近5次有效送货按单合计作为参考；达到最大量绿、达到最小但不足最大黄、低于最小红。缺历史或冻结单位不可靠时灰色；失败和过期响应不当零或绿。
- 明确产品补库收料自动进入待加工，超计划到货部分保留原纸。实际加工只扣本次投入，默认以子件入库，余量继续待加工；按冻结配方实际组套，余下子件留原位。
- 加工子件用冻结实物身份参与订单抵扣，不再按原纸外接尺寸裁切，不再次乘模数。订单预占、补库覆盖、实际组套、取消释放和撤销使用共同资格；集货、子套占用和不合规货位不被二次采用。
- 相同提交重试保持原操作键；服务器确认保存后，刷新失败明确说明已保存，避免员工再次建单。

## 已复现及审查发现

1. 已加工子件可能再次进入矩形裁切并重复计算产量。
2. 原完整批次完工入口无法表达只加工部分原料，需要明确实际投入和未加工余量。
3. 旧送货缺冻结换算时，不能从当前或订单比例推测实际历史扣库量。
4. 同一组套成功后全部子件已用完，重试仍需识别原提交，不能因来源不再可用而把成功变失败。
5. 新库存子件实际组套后的送货就绪判断必须认同真实成套预占，不能被旧原料到货状态误拦；此项完整送货接口验证是发布门禁。
