# 订单作废后Excel重新导入 — 隔离修复，尚未正式发布

## 问题原因

当前正式v0.22.699/262d1078、revision ew1020em。用户已确认入口为订单页导入Excel。

1. `_order_import_preview` 对位置清单模板只查询历史文件哈希是否有来源记录，没有核对关联订单是否已作废/删除，直接返回duplicate_skipped；页面因此显示“重复订单已跳过”。
2. `order_import_source.prepare` 的保存去重永久绑定原来源键；已cancelled仍回放原作废单，修改数量则409，物理删除后来源FK为NULL又被当异常阻断。
3. 客户单号层已排除cancelled，文件来源层却未同步，因此只修客户单号或前端按钮不能闭环。不能靠重命名文件解决，去重依据是文件内容摘要。

## 修复规则

- 手工PDF/Excel按来源哈希找唯一仍有效订单。有效订单保持幂等回放/异载荷拒绝；同批重复、跨客户、权限、库存/CAS及事务门禁不变。
- 同一来源只有作废单或有完整正常删除审计时，新保存请求创建后继来源和新订单。后继键绑定上一次来源ID，原哈希/来源行/旧订单及审计全部保留；不删除去重记录，不复活旧单，不增加操作步骤。
- 位置清单预览与保存、结果核对使用同一来源资格。重新导入后的再次上传正确指向最新有效单。
- 只撤回报料/采购、整单仍有效，不允许因此重复建单。NULL来源需原创建+对应删除审计及明细解绑证明；证据不足显示具体缺少删除审计，不猜成已删除。
- SQLite删除后可能重用数值ID；原请求键重试/结果核对同时校验订单号，防止旧请求误指向新订单。
- 邮箱附件的独立发生身份、人工删除/处置和队列协议保持，不自动重开历史邮件任务。
