## 核查原因与修复

1. 原采购逐行撤销对所有统一采购来源一律阻止，补库实收撤销又一律要求走不存在于该入口的“受控库存调整”，形成操作断路。现允许管理员针对单一完整补库来源逐笔回退：取消待生产安排或先撤已加工记录，再撤实收，最后撤选中采购明细。保留订单型统一采购现有受控规则，不扩大到其他来源。
2. 收料事实多数通过stock_replenishment_item_id关联，而非supplier_order_item_id；现按真实来源追踪，保留已确认供应商月结、生产、预占、损坏报废、数量和来源身份检查。采购行撤销只解除对应来源并重算该采购单，其他明细和历史保留，原补库需求可以重新采购。
3. 接口来源锁后二次校验撤销事实，修复并发同键重放；新实收在来源锁后重新确认有效采购绑定，避免采购已撤仍按旧读取继续入库。事务、版本、审计与客户权限不删除。
4. 产品查询只追原实收片料，遗漏已加工产出。新增“已完成加工任务→确切产出批次”的双向身份核验，沿实际移库链读取现存位置；不按同编码猜批次、不增加适用产品绑定、不把片料改为成品。桌面和手机查询及库存优先排序同步补齐。
5. 查询用语为“已加工片料”；单笔入库选项明确为“片料 / 半成品入库”或“完整成品入库”，不改变原输出默认值、数量算法和冻结记录。
