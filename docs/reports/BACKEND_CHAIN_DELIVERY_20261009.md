# 送货后端十项审查

基线：正式 v0.22.592 / 8e50a807。测试均为合成隔离库和离线页面方法，不在正式页面点击或写业务数据。

| 项 | 风险 | 结果与证据 | 最小方案 |
|---|---|---|---|
| D01 | 待发货数量编辑提交幂等标识 | 确认Bug。现行行内编辑发送标识，普通编辑后端400；新API用例修前失败 | 普通编辑沿用持久幂等记录，按动作/用户/内容核对；同键重放、异载荷拒绝 |
| D02 | 普通新建断线或服务器异常后重试 | 确认Bug。创建接口拒绝防重标识，而无标识相同请求不具备去重合同 | 普通创建接受独立动作幂等键；页面相同载荷保持同键，变化才新键；原请求跨日重放返回原结果 |
| D03 | 来源字段合法校验与执行不一致 | 确认Bug。source_type=' order '校验通过却过滤掉全部明细，返回201和数量0 | 在输入模型统一去空白/别名；保存始终使用同一规范值 |
| D04 | 全空白修订标识 | 确认Bug。8空格通过长度检查，转成None后.strip触发500 | 先规范化再校验长度；非法请求422，零写入 |
| D05 | 编辑取得写锁前版本变化 | 确认Bug。数据库版本在读取后、认领前变化时，旧ORM对象仍使编辑返回200 | 将预期版本放入同一条件UPDATE；版本变化409，事务回滚 |
| D06 | 重复确认发货多扣库存 | 定向回归通过 | 维持pending原子状态认领和实际预占消费 |
| D07 | 一行失败仍保存其他行出库 | 定向故障回归通过 | 整批事务回滚保留 |
| D08 | 不同客户订单混入同单 | 定向API回归通过 | 客户范围和订单归属保持 |
| D09 | 已发货受控修改重复冲销/扣库 | 定向回归通过 | 原批次恢复、旧明细退休、新版本消费、幂等保持 |
| D10 | 有回单后修改送货事实 | 定向回归通过 | 回单/财务下游阻断保持 |
| D11 | 应用实际拿货后旧编辑页覆盖数量 | 确认Bug。实际拿货80/50应用后版本仍1，旧页无法识别原100/50已变更 | 应用拿货同事务按版本认领并递增版本，旧编辑提交409；不改变订单数量 |

边界：本次保证同一保存请求标识的重试幂等；关闭页面重新建立的新请求不自动视作旧请求。未知网络结果仍保留原有查列表提示和禁止原窗口重复提交保护。保留客户范围、普通日期限制、历史补录权限、冻结打印合同和既有库存流水。
