2026-10-10。根已完整读取 api/REPORT.md 与 ui/REPORT.md；正式仍 v604 / 75129569ed5ff0bf454d075471c9b4fd902b070f / en1009hp。此页为方案，实施须待独立合同复核及新任务卡，不把审查通过写成已修复。

## 已证实的问题

- 页面未校验保存返回内容，空白或不完整的 2xx 也提示成套入库成功。
- 结果未知时，原请求仅保存在弹窗内存；改数、关窗重开或刷新会丢失原保存标识与完整内容，无法可靠核对本次入库。
- 旧账号组套请求的迟到 401 可先触发全局登录副作用；页面已有响应代次检查未覆盖该副作用。
- 服务端保存了不可改的组套请求与结果，但缺少按原请求只读核对的合同。历史入口按组计划查询，不能拿保存键的 404 或当前列表消失证明未执行。

九个真实合成 API 场景和十个实际页面方法观察支持上述结论。原键精确重放、异载荷冲突、旧版本拒绝、冻结配比、成本门禁、全部事务回滚有效；不计为 Bug，不称原键二次扣库。页面刷新后发起新批次，是新业务，风险在原批次未知而未核清。

## 交付后的员工流程

1. 填本次实际套数及成套位置，正常保存一次。首写前可靠保存当前账号、独立操作标识和完整原内容。
2. 完整保存证明通过后，显示本次套数、成套位置、逐子件实际消耗及本次组套后余片。
3. 断网、超时或回执不完整，显示“查原组套结果”，保留原内容并锁定该组后续入库，其他组仍可操作。
4. 已保存则恢复原结果；查询时未见记录仍保留原请求，员工明确继续时使用原标识与原内容。无法核对的旧记录给可读追溯和管理员核对依据。
5. 列表刷新、追溯读取或本机清理失败与业务保存结果分别显示。

## 后端边界

- 仅 group_stock / action=assemble；另建专用恢复服务和只读端点，保持当前 GroupAction 默认字段、数组顺序、lot_id:null 规范化与旧请求签名。
- 原算法忽略的 disposition、actual_output、原料 lot_version 和逐行目标字段仍参与原请求签名，不额外强制其等同本次成套事实，不照搬 dispose 的新加工约束。
- assemble 可选 builder 在最终 Command 首次 INSERT 前冻结结果；输出创建、成本继承、清空栈板之后，原后置共用登记与事务顺序保持。任何后续失败连同证明整体回滚；不 UPDATE 历史 Command。
- 证明的 members 为原 jobs 全集合，inputs 仅真实取用子集，按 job/lot 精确映射。支持同产品多 job 和取用为零的成员。
- 余量从本次真实消耗流水前后量冻结，不能用首次加工入库量减本次消耗；考虑多次部分组套和后来取用。
- 只读核对检查当前权限/归属与原冻结身份，不用当前报料状态、可用数量、启用状态或 BOM 写入资格代替原保存事实。
- 新写仍在原写锁和事务中检查所有现有来源资格；同键重放不重新执行生产。
- expected_actor_id 只作当前认证账号匹配保护，排除在旧业务签名外；proof 不含成本。旧无完整证明记录仅 legacy_trace，不回填。
- 本轮无迁移、无历史业务数据改写，不提供永久注销未知请求。
