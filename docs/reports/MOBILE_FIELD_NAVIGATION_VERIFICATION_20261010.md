# 手机查货返回与现场触控：方案及根复核

任务 MOBILE-FIELD-NAVIGATION-20261010，承接正式v599。现行源码与隔离Chrome先复现，再实施；本报告发布前为开发验证记录，正式状态以文末实际发布回执为准。

## 问题与处理

1. 查货→产品货位→盘点→返回时，原关键词和选中产品消失。四个盘点入口统一记录独立来源；返回查询重新读取当前库存，不保存库存数量。
2. 扫码盘点的可见返回走地图，丢掉产品筛选。返回固定同源/q/正整数货位及可选24位hex产品筛选；非法入参安全降级。扫码脚本更新唯一资源版本，避免继续使用旧跳转。
3. 初始pageshow重复加载地图，可能覆盖focus_only又打开空位盘点。初始展示不重复加载，浏览器缓存返回才先重核身份、清除旧事实并读取当前库存。
4. 原批次卡固定220px内部滚动，长编码和动作被裁切；32～36px按钮偏小。取消该裁切，现场关键按钮至少44px，长编码换行；盘点提交紧跟批次，添加表单在后，保持原模式显隐。
5. 恢复过程中失去权限或账号核对失败可能留旧地图、隐藏重试。清除旧地图/货架/库存内容，退出无权限页面，主查货页和当前地图均提供重试。搜索、明细、地图和身份请求使用当前操作检查，过期200/401不能接管新产品或账号。

导航记录按认证账号、独立随机token保存，8小时有效，每账号最多20条，只清理专属导航前缀。存储失败降级为重新查货；不清盘点/取用原请求。恢复原选中产品直接读现行权限接口，不以搜索前20项是否包含它判断可见性。

## 保持的业务边界

待核对盘点只有在原请求已可靠保存时可返回查货，原货位输入和提交仍冻结，再进入保持原key/body/实盘数量；不自动重发。提交进行中、账号变化、全局存储异常、初始入库在途或未知仍阻止返回。位置不对的批次搬运继续使用原lot用途。v599恢复组件、初始入库运行时及所有后端业务服务未改。

本轮不写正式业务接口，不调库存、订单、价格、位置或历史，不做迁移。未知请求安全终止仍是独立后续，不将not_found当作取消成功。
