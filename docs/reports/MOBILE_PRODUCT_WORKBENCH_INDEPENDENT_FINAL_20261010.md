## 独立证据

1. `independent-api.xml`：2 个合成真实 API 节点通过，7.269 秒。已加工子件 summary、位置、扁平 items、实际 lot 反查统一显示片；底层 lot.unit、实存/可用/预占和版本不变。受限账号无跨客户绑定时 404，加入明确 allowed-product 后仅返回当前客户候选，原 owner 隐藏。取数阶段 SQL 监听没有 INSERT/UPDATE/DELETE/REPLACE；授权/绑定等准备只在合成夹具中写入。
2. 同 2 节点中的整数边界：search 与 free reverse 的最大合法计算 offset 返回 200 空页；page 本身仍在整数范围内、但下一页的 offset 溢出时返回 422。product/customer/known_customer/lot 四种超范围编号均为 422；最大合法但不存在的 product ID 为 404。库存事实前后相同。
3. `independent-ui.json`：最终精确 UI 的 **5 个独立检查区块全部通过**，执行实际工作台 JS、原图纸组件和 linkedom 事件。真实 API 明细中的加工子件显示 `10 片`，从该行“查用途”再提交仍保留原 lot_id 与 `output_piece`。作者真实 hidden/null/inactive 三包合法显示；删掉授权 summary、groups、production.process_steps 的三个损坏回包拒绝并可重试。
4. 手机图纸检查：使用真实 `mountMobile`、原 `TmProductDrawings`，只为预览测试加入明确标记的合成 PDF 元资料。展开前预览 fetch 为 0、没有 img；展开才取预览。切详情取消旧预览，迟到旧 blob 不显示；新详情展开加载，收起释放 blob。换账号重新挂载后，旧搜索返回不渲染。这里的 fetch/blob 都为受控离线替身，不冒充实际附件下载或真实浏览器验收。
5. 有限等待检查：触发实际 15000ms 定时回调，忙态结束并给重试；未提交草稿 B 保留，重试仍发已提交条件 A。故意不遵守 abort 的旧返回不覆盖新结果。A 的旧历史读取也不能改变 B 产品的 production 页签。使用虚拟时间，没有宣称实际等待了 15 秒或验证真实网络环境。

API 的 15 条独立真实响应保留 `response.text`、解码 body 与状态；`verification.json` 对每条原文给 SHA256，并核对原文解码等于 body。作者 14 个 `fix-http` 文件保留为实际响应的解码归档，另记文件 SHA，不将未保存的原始 HTTP 线数据冒称为原文。独立探针、XML、JSON及候选源文件 raw/LF 指纹均在机器索引中。

## 发布前拦截及修正

初始候选 d75 的 `independent-ui-before-followup.json` 保留真实失败：

- 打开 A → 切反查 → 空长宽本地校验错误 → 点重试，会再次 GET A 并打开旧产品。原因是 lastProductId 残留，重试没有区分当前表单校验与之前详情请求。最终补丁用当前表单重试状态，并在切模式/关闭时清理目标；原流程现在 **0 个 GET**，不打开旧产品。
- 授权库存 `{summary:{},groups:{},items:[]}` 被当成正常空库存。属于原坏 2xx 根因的边界变体，不另计新根因。最终要求三个稳定库存组及页面所需数量/单位、positions 数组，hidden_by_permission 保留例外；不重新计算业务数量。

另由独立源码预审指出、UI 作者实际红测确认的 output_piece 表单缺选项，已在最终候选补齐。原状态被表单重建丢弃、服务端默认 raw 的路径被消除；没有更改实际物料状态或匹配算法。
