# 补库保存与原单恢复 v614 发布回执

2026-10-10 已技术发布 **v0.22.614**。本闭环解决补库保存误报、原请求丢失及原单恢复；完整保留正式v613的加工身份冻结和手机全部图纸。管理员页面及现场业务验收待反馈，不称全ERP全部无缺陷。

## 问题与修改

| 原问题 | 修改后的行为 |
| --- | --- |
| 空、部分或数量不一致的成功回包会直接显示已保存 | 同时核对原请求、操作人、单号、完整来源行和数量；外购还核实际采购量及原换算，不能仅凭HTTP成功关闭表单 |
| 超时、刷新或重开后丢失原内容，容易换新请求再建单 | 保存发送前按账号持久保留完整原内容；提供“查原结果”“按原内容继续”“查看原单”，未知后拒绝也不清除原请求 |
| 多页面拒绝与未知请求交错，可能解锁同一来源 | 独立保留未知记录并在发送前再次合并核对；同来源未确认时阻止重报，其他来源可继续 |
| 旧账号迟到响应覆盖新窗口，无响应一直等待 | 绑定账号与窗口状态、有限等待，迟到成功/失败不污染当前表单；成功后打印或列表失败保留原单 |
| 原单作废、收料或主档变化后无法准确查询 | 只读查询原保存事实，同时显示当前收料/作废/采购取消状态；不再次采购，不按当前新建资格否定原事实 |
| 合法材质层数或供应商派生值被当成请求不一致 | 完整请求仍原样校验；实际值从原持久记录读取，提示字段不冒充权威字段 |

后端新建只有在commit前成功装配完整证明才提交；证明缺失或异常整体回滚。已有历史NULL或缺少稳定来源时仅给原单线索，不补造证明。员工审批、physical二段采购保持独立协议，权限、客户范围、版本、数量、事务和审计门禁保留。
