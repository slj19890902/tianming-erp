# Phase 7 送货事务与标准打印设计

## 数据隔离

旧库已有 `deliveries`、`delivery_items` 及回单、对账外键。新送货模型使用
`sales_deliveries`、`sales_delivery_items` 和 `delivery_daily_sequences`，旧表不改名、不删除、不写入。

## 事务边界

- 创建送货单只生成待发货草稿，不提前累加订单已送数量。
- 确认发货在单一数据库事务内完成。
- 每条订单明细使用带条件的原子更新：
  `material_status='received'`、未强制结案、剩余数量足够。
- 任一明细更新失败，整张送货单、订单数量和审计日志全部回滚。
- 送货单状态通过条件更新从 `pending` 变为 `dispatched`，重复确认返回 409。

## 状态

- 明细全部送完或已强制结案：订单状态 `delivered`。
- 至少一条明细已送但仍有尾数：订单状态 `partially_delivered`。
- 未送货：订单状态 `pending_delivery`。
- 强制结案仅允许未完全发货且尚未结案的明细，并记录原因和审计日志。

## 权限

- `admin`、`finance`、`sales`：查看、创建、确认发货、强制结案。
- `workshop`：仅查看待发货和打印数据。

## 打印安全

`GET /api/deliveries/{id}/print` 使用显式字段白名单，禁止返回价格、金额、成本字段。
打印页不包含任何金额变量、绑定或隐藏列。

## 单据格式

打印页标题固定为“苏州天明包装有限公司 / 送货单”，展示客户联系方式、地址、单号、
日期、车号；明细列固定为客户单号、款号及品名规格、PCS、数量、备注；底部展示总量、
三联说明及四处签字横线。
