# WMS 固定二维码来料系统设计

## 目标

为车间手机提供局域网内的固定二维码入口，完成待收料查询、并发安全入库、24 小时内撤回和审计追踪。

## 架构

- `sales_order_items` 增加 `material_received_by`，关联当前操作用户。
- `app/api/incoming.py` 提供只读列表和受 RBAC 保护的状态操作。
- 入库使用带旧状态条件的单条 `UPDATE`，以受影响行数判断重复点击。
- 撤回要求原因，且所属订单进入 `delivered` 或 `partially_delivered` 后拒绝操作。
- `static/incoming.html` 使用现有 HttpOnly Cookie 登录态，不在浏览器保存凭证。
- `scripts/generate_wms_qr.py` 生成指向局域网入口的 PNG 二维码。

## 权限

- `admin`、`workshop`：查看、入库、撤回。
- `sales`、`finance`：仅查看。
- 未登录：API 返回 401，移动页显示登录失效提示并引导返回首页登录。

## 数据与排序

- 待收料按 `delivery_date IS NULL`、交货日期、订单号、明细 ID 排序。
- 最近已收按当前 UTC 时间向前 24 小时过滤，按入库时间倒序。
- 返回订单号、客户、产品快照、规格、材质、数量、交货日期和操作人。

## 错误处理

- 重复入库返回 409。
- 不存在的明细返回 404。
- 撤回原因为空返回 422。
- 已发货或部分发货订单撤回返回 409。
- 所有成功入库和撤回均写入 `operation_logs`。

## 验证

- API 自动化测试覆盖角色、排序、并发条件更新、24 小时过滤、撤回原因和发货拦截。
- Alembic 测试确认旧 `orders` 不变。
- 浏览器按手机视口验证页面身份、非空内容、控制交互、控制台和截图。
