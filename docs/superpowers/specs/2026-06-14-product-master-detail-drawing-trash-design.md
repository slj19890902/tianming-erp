# 常用箱主从视图、图纸版本与产品垃圾站设计

日期：2026-06-14  
状态：待最终确认  
选定界面方案：A，高密度客户列表

## 1. 目标

在不破坏历史订单、报料、库存和送货数据的前提下，完成以下改造：

1. “常用箱与材质”采用“先选客户，再管理产品”的主从视图。
2. 修复产品编辑时因编码、名称和 `/` 拆分造成的崩溃。
3. 将产品图纸升级为可追溯的多版本画廊。
4. 将产品删除改为 30 天垃圾站，可恢复、可清理。
5. 彻底区分“停用”“移入垃圾站”“永久归档/物理删除”。

## 2. 页面与交互

### 2.1 第一层：客户主列表

- 默认只展示启用客户。
- 顶部提供客户名称、客户编号、拼音首字母搜索。
- 每行展示客户名称、常用箱数量、客户状态和进入按钮。
- 点击客户后进入该客户的常用箱列表。
- 保持高密度表格风格，不使用低密度大卡片。

### 2.2 第二层：客户常用箱列表

- 顶部显示面包屑：`常用箱与材质 > 客户名称`。
- 提供“返回客户列表”“新增常用箱”“垃圾站”入口。
- 搜索支持存货编码、规格、材质、楞型。
- 默认隐藏停用产品和垃圾站产品。
- 列表不重复显示客户名称。
- 隐藏“品名”列。
- 原“客户料号”表头统一改为“存货编码”。
- 每行提供：编辑、停用/启用、移入垃圾站。

### 2.3 产品编辑弹窗

以下字段完全独立，不再互相拼接或拆分：

- `product_code`：品号。
- `customer_material_code`：存货编码。
- `product_name`：产品名称。
- 长、宽、高和展示规格。
- 材质、楞型、工艺、价格和备注。

移除前端所有基于 `" / "` 的强制拆分、监听和回写逻辑。用户清空任一字段或输入 `/` 时，弹窗不得关闭、组件不得卸载，其他字段不得被覆盖。

## 3. 产品状态与垃圾站

### 3.1 三种状态

1. 启用：`is_active = true` 且 `deleted_at IS NULL`。
2. 停用：`is_active = false` 且 `deleted_at IS NULL`。
3. 垃圾站：`deleted_at IS NOT NULL`。

新增字段：

- `deleted_at`：进入垃圾站时间。
- `deleted_by`：执行删除的用户。

### 3.2 删除规则

- 普通“删除”不执行 SQL `DELETE`，改为写入 `deleted_at`，产品进入垃圾站。
- 垃圾站产品不出现在客户产品列表、新建订单和新建报料搜索中。
- 历史订单仍使用快照和原产品关联正常展示。
- 30 天内支持恢复，恢复时清空 `deleted_at` 和 `deleted_by`。

### 3.3 清理规则

- 未被任何历史业务引用的产品，可从垃圾站物理删除。
- 已被订单、报料、送货或其他历史记录引用的产品，不物理删除；“清空垃圾站”只将其永久归档并从垃圾站操作界面移除。
- 该限制是数据库完整性要求，不能通过级联删除绕过。
- 所有删除、恢复、清理动作写入 `OperationLog`。

推荐新增字段：

- `purged_at`：垃圾站清理时间。对于被历史引用的产品，表示永久归档，不代表物理删除。

## 4. 图纸版本模型

新增表 `product_drawings`：

- `id`
- `product_id`，外键到 `products.id`，`ON DELETE RESTRICT`
- `image_path`
- `thumbnail_path`
- `uploaded_at`
- `uploaded_by`

`Product.drawings` 建立一对多关系，按 `uploaded_at DESC, id DESC` 排序。第一条为当前生效版，其余为历史版本。

### 4.1 迁移策略

采用两步无损迁移：

1. 第一版迁移创建 `product_drawings`，将非空 `products.drawing_path` 转为一条图纸记录。
2. 应用代码改为只读写 `product_drawings`，并验证迁移数量和文件存在性。
3. 在验证和备份完成后，再通过单独 Alembic revision 删除旧 `products.drawing_path`。

不在同一个 migration 中边复制边删除旧字段，避免 SQLite 表重建失败时丢失图纸路径。

### 4.2 图纸文件

- 高清图和缩略图继续保存在 `static/uploads/drawings/`。
- 数据库只保存相对 URL，不存 Base64。
- 上传新图纸只新增版本，不覆盖旧文件。
- 删除单个图纸版本时，先删除数据库记录；事务成功后再清理对应文件。
- 若文件清理失败，记录日志，不回滚已经确认的数据库删除。

## 5. API 契约

沿用当前产品路由前缀 `/api/master/products`。

### 5.1 产品与状态

- `GET /api/master/products?customer_id=...`
  - 默认过滤 `is_active=true`、`deleted_at IS NULL`。
  - 管理页可通过参数查看停用产品。
- `GET /api/master/products/{id}`
  - 返回产品详情和 `drawings[]`。
- `PUT /api/master/products/{id}`
  - 独立更新编码、名称、规格、材质等字段。
- `PUT /api/master/products/{id}/status`
  - 只负责启用和停用。
- `DELETE /api/master/products/{id}`
  - 改为移入垃圾站，成功返回产品垃圾站状态，不再触发外键 500。

### 5.2 垃圾站

- `GET /api/master/products/trash`
- `PUT /api/master/products/{id}/restore`
- `DELETE /api/master/products/{id}/purge`
- `POST /api/master/products/trash/empty`

路由静态路径必须在 `/{product_id}` 动态路径之前注册，避免 `trash` 被解析成产品 ID。

### 5.3 图纸

- `POST /api/master/products/{id}/drawings`
- `DELETE /api/master/products/drawings/{drawing_id}`

保留旧 `POST /{id}/drawing` 一段兼容期，内部转调新版本服务，待前端全部切换后再移除。

## 6. 权限

- `admin`：编辑、启停、移入垃圾站、恢复、清理、图纸上传和删除。
- `sales`：查看、编辑、启停、图纸上传；是否允许移入垃圾站沿用现有产品删除权限。
- `finance`、`workshop`：只读，敏感价格字段继续按既有 RBAC 隐藏。
- 清空垃圾站仅限 `admin`。

## 7. 数据迁移安全

- 迁移前执行 NAS 备份。
- Alembic 脚本禁止删除历史订单、报料和产品关联数据。
- 新增字段先允许空值或提供服务器默认值。
- 图纸路径迁移使用 `INSERT ... SELECT`，保持幂等保护。
- 迁移后检查：
  - `PRAGMA integrity_check`
  - 旧 `drawing_path` 非空数量与新图纸迁移数量
  - 产品总数不变
  - 历史订单和报料关联数量不变
