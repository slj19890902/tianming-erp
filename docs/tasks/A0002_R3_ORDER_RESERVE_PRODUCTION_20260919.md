# A-0002-R3 订单派生备料转产接线

老板要求按融合审计提示词继续推进；只有明显前端变化才请求页面验收。本轮从实时正式基线01b1d9d7建立独立分支`codex/a0002-r3-order-reserve-production-20260919`；发布前合入随后正式发布的 R07 基线346a74d5。

## 现场问题与目标

订单500只、采购600张并按冻结用途收料后，订单用途500张自动形成500只成品，余100张成为同客户通用片料。现有后单可以预占和耗用该批片料，但无订单转成品入口仅识别独立补库采购收料，因此订单派生的100张无法在既有“生产与成品→待安排”中受控转产。

最小目标：将冻结用途分配产生的`semi_finished_reserve`收料批次接入现有备库生产列表和动作事务。目标产品仅允许来源订单明细的同客户有效普通产品；投入数量、冻结开数、每箱片数和实际库存版本沿用正式快照。查看不写数据；安排只预占；确认产出原子地耗源并增加成品；重放、异载荷、旧版本、客户范围、权限、撤销及审计沿用现有机制。

## 不变量和禁止范围

- 不新建平行库存或生产表，不伪造补库采购，不修改原采购、收料或订单数量。
- 只接受已发布且未冲正的冻结用途分配、`source_kind=order_item`、`component_type=whole`、正数备库用途、仍为活动状态的原片料批次；BOM组件等复杂来源继续拒绝。
- 产出成本继承投入片料实际采购成本；一张多出和每箱片数使用采购用途冻结快照，不能读取后来修改的常用箱换算。
- 保留客户范围、角色、状态、CAS、幂等、事务、审计、位置发布及回滚门禁。无正式数据修复，无历史回填。
- 先用合成临时SQLite覆盖500/600/100、部分投入、重放、异载荷、旧版本、客户隔离、失败回滚和撤销；正式页面不自动点击。

无数据库结构变更优先。若实现证明必须迁移，停止编码并先补迁移方案及三份迁移文档门禁。
