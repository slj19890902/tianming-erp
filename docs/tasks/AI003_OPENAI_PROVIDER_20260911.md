# AI-003 库存助手 OpenAI 真实解读适配器

状态：开发中。老板已授权安全创建 AI 密钥；OpenAI 安全窗口仍等待组织/项目选择。本任务先补齐可离线验证的真实 provider 代码与安装助手启用逻辑，密钥创建、首次真实调用和正式启用必须等安全窗口回执后完成。

## 目标

- 使用 OpenAI Responses API 对 ERP 本地生成的脱敏库存快照作只读中文解释。
- 强制结构化输出，结果继续经过 ERP 白名单、证据引用、长度和禁止内容校验。
- 不向模型提供 ERP 工具，不发送 PDF、邮件正文、电话、地址、Cookie、数据库路径、日志或密钥。
- 安装助手保存密钥后仅向受管 ERP 子进程注入，并自动启用 OpenAI provider；未配置、密钥无效、超时、限流或上游失败时安全降级，原库存经营看板继续可用。

## 不变量

- 模型不修改订单、报料、采购、库存、生产、送货或财务事实。
- 数量、成本、需求、库龄和匹配仍由 ERP 确定性逻辑计算。
- 权限、客户范围、幂等、运行/用量台账、审计和事务门禁保持不变。
- API 密钥不进入 Git、业务数据库、日志、发布包或 NAS 备份。
- 不用测试密钥调用真实网络；通过受控假响应验证请求内容、结构解析、错误降级及秘密不泄露。

## 验收

1. 生产环境仅在明确配置 OpenAI 且存在有效本机密钥时显示启用。
2. 请求固定发送到 OpenAI Responses API，`store=false`、无工具，使用严格 JSON Schema。
3. 正常响应提取结构化 JSON 和 token 用量；无效结构、401、429、超时和网络失败返回安全错误码。
4. 安装助手重启服务后自动注入 `OPENAI_API_KEY` 与 provider 标识，环境文件和状态文件不含明文。
5. 既有 disabled/mock、权限、幂等、审计和页面降级回归通过。
