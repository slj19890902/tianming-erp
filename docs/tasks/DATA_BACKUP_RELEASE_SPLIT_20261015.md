# 数据备份与程序发布拆分（2026-10-15）

状态：隔离收尾候选，正式故障未解决，尚未正式发布。本任务不授权正式发布、正式数据回退、删除既有备份或 NAS 操作。

## 2026-10-15 收口决定

- 正式故障只准备[最小恢复交接](../release_reports/FORMAL_ERP_RECOVERY_HANDOFF_20261015.md)，不再重复核查已确认的权限阻塞，不执行任何新发布、迁移、恢复点任务或正式启动。
- 隔离分支只提交现有备份拆分、有限故障收尾和可复现测试；不合并、不部署。真实业务原件的完整恢复未通过，既有完整恢复点全部保留。
- “禁止继续发布”不等于“所有故障保持业务停服”。只有直接确认数据库兼容且没有活动迁移，才可按既有协议恢复最后健康程序；未知状态不得盲启或覆盖数据库。
- 本轮不修 v0.22.634，也不因此创建正式新版本；使用已验证的 v0.22.635 做有界隔离重启和故障恢复测试。

## 现场边界

- v0.22.639 原事务只读核对；不得启动第二个发布/迁移/备份进程，不强杀已有进程，不改变原事务恢复规则。
- 优先恢复业务；只能使用已有正式管理协议和既有授权，不要求用户再次输入管理员密码。
- 正式实例、正式数据库、现有 `.tmbackup`、唯一程序版本和恢复依赖均不删除、不覆盖。
- 单代理、单一既有隔离副本、定点测试；不重构业务 ERP，不修改普通业务数据。

## 2026-10-15 进度审核后的优先级

1. 正式业务恢复是最高优先级；监督程序版本不代表业务程序已启动或数据库已升级。
2. 现场只允许一次有界只读核实。若当前普通账号没有免密恢复通道，停止尝试并明确记录“正式业务仍停服，恢复受权限阻塞”。
3. 本轮不新增正式发布、数据库回退、删除备份、管理员授权或 NAS 操作；不得用 10 月 10 日隔离副本覆盖正式库。
4. 开发范围收窄为轻量数据恢复格式、15 分钟容量/耗时测量、停服前门禁和既有失败收尾验证；不改监督程序安装结构，不部署新格式。

## 停服前硬门禁

下列条件必须全部在旧版仍服务时得到持久、可回读的证明，缺一项就不得开始停服：

- 候选已构建并完成定向测试，签名程序包、来源和结构合同校验完成；
- 磁盘空间满足最终一致性快照、临时文件及回读，不依赖停服后的旧备份清理；
- 数据库快照、不可重建业务原件、必要配置/密钥及对应程序包均可取得，恢复工具支持该格式；
- 迁移演练（如有）完成，当前数据库 revision 与迁移起点已直接确认；
- 发布驱动、持久日志、状态回查和经过验证的失败恢复路径在管理员授权有效期内持续可用，不依赖临时 sudo 缓存或聊天输出管道；
- 已区分本次部署临时停服与用户主动长期停服，失败收尾不得无条件清除原有人工停服标记。

常规无迁移更新不重装监督程序、不重复打包未变化的 runtime/OCR。程序复制、签名校验、解包和可提前完成的恢复演练全部放在停服前；停服后只保留最终一致性确认、程序指针切换和健康启动。隔离目标为停服不超过 60 秒，未实测通过不得宣称达标。

## 本轮最小闭环

1. 量化旧完整恢复包的数据库、业务原件、配置、程序运行环境、OCR、缓存、旧程序和历史备份构成；区分输入大小和最终密文包大小。
2. 新增独立数据恢复格式：SQLite 使用在线 backup API 生成一致性快照；数据库外不可重建业务文件和必要配置进入数据包；签名程序只保存内容身份引用，不重复打包。
3. 旧 `tianming.recovery.v1` 完整恢复继续兼容；新数据格式必须由正式恢复代码验证数据库、文件清单、签名程序身份和结构合同后，才允许恢复到全新目标。
4. 15 分钟数据库快照与发布解耦，保留多个时点；迁移前仍生成对应数据恢复点。NAS 同步是独立任务，本轮不调用。
5. 发布前完成构建、签名包验证和迁移演练；停服窗口只保留最终一致性捕获、迁移与切换。清理失败在空间足够且恢复点有效时只告警，不把业务保持停服。
6. 发布/备份任务写持久状态和日志，公开摘要只含阶段、文件数、字节数、耗时和脱敏错误分类；聊天输出断开不能终止后台任务。

## 验收

- 在线写入场景下 SQLite 快照一致、完整性通过，源库无需停服；重复时点互不覆盖。
- 新数据包不包含程序运行环境或 OCR 模型；恢复时必须提供摘要匹配的签名程序包。
- 数据库外业务原件不漏备；缓存、运行日志和 SQLite WAL/SHM 不冒充业务原件。
- 新数据包在隔离空目标实际恢复，关键表计数、revision、业务文件摘要与源一致；错程序、缺文件、篡改、旧预览全部拒绝。
- 旧完整恢复用例不回归；不通过删除断言、放宽结构/附件/签名检查获得成功。
- 输出 15 分钟频率的容量/耗时测算、阶段耗时和真实停服边界；未执行正式发布时明确写“尚未正式发布”。
- 分阶段计时必须至少包含在线快照、`integrity_check`/`foreign_key_check`、压缩、加密、最终落盘、独立回读、恢复解密/解包及启动；“外键 0”只表示 `PRAGMA foreign_key_check` 返回零条违规。
- 持续写入导致 SQLite backup 进度反复回退时必须在限定时间失败且不发布半成品，后续时点重试；不得无限占用定时任务。
