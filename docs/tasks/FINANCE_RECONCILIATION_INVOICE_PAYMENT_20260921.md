# FINANCE_RECONCILIATION_INVOICE_PAYMENT_20260921

状态：已实施，待正式发布门禁与管理员人工验收。

## 目标

实现客户对账到开票任务、收款和完成的待办闭环。查询按客户及账期稳定分页；同一客户的不同账单可以同时处于不同待办队列，角标只按可见范围内的去重客户计数。

## 边界

- 不回写、补建或删除正式客户、订单、回单、对账、开票或收款业务事实。
- 复用已有对账异议、真实回单更正、跨账期调整、开票任务、收款流水、版本、幂等与审计机制。
- 本次无数据库 schema 或数据迁移；migration head 保持 `du0920`。
- 税局 Excel 仍是商品明细导入文件；购方资料仅在任务冻结资料、展示和备注复制中使用，不宣称自动写入税局发票。

## 实施内容

- `app/api/finance.py`：增加全部未完成账期队列、统一服务端队列判定/客户去重角标、稳定排序分页、待修改/异议待修改、已开票待收金额。
- `app/api/invoice_tasks.py`：撤销未实际开票任务时校验版本、收款、已开票和其余有效任务；满足条件才将账单退回待修改并写审计。
- `static/index.html`：增加待办入口及角标、导出并确认、开票任务确认下载/重下、受控撤销、收款表单和完成状态展示。

## 定向验证

- 服务端：多账期同客户去重角标、客户筛选、待开票/待收款/已完成归属；未开票任务受控撤销退回、已开票拦截；既有异议、签收回单更正、跨期调整、收款版本及幂等保护。
- 前端：导出失败不确认、确认失败可重试、生成任务单飞、开票确认与登记单飞、收款单飞、Vue 全模板/JavaScript 编译。
- 发布前补做：最新正式基线、唯一 migration head、签名包、正式备份和只读健康/接口/静态资源/数据库完整性核对。
