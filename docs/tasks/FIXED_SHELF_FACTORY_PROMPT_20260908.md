# 工厂 Codex 接入提示词

请接入 `origin/codex/fixed-shelf-picking-20260908` 的固定货架、标签、扫码拿齐和集货功能。先阅读当前工厂仓库规则与 `docs/tasks/FIXED_SHELF_HANDOFF_20260908.md`，核对交付提交、当前分支、未提交工作和迁移链。候选已基于 `factory-current-baseline@0cf77140`（v0.22.280），包含工厂最新空间编号及手机货架导航修复；若工厂又有更新，保留其更新后再集成，不覆盖目录。

用户已确认：员工在货架旁拿到货就扫码，扫码只标记该款拿齐，不登记集货或发货。货物随后集中到固定待送/集货区，再由实际操作人员确认集货，最后装车发货。正常扫码打开页面后自动保存，无需再按“拿齐”；第一次需登录，同款对应多张任务时先选定任务。扫码不会替代员工对实际数量的核对，缺货或多货位来源仍走明细异常处理。

请按以下顺序执行，不重新设计整个仓库模块：

1. **只读核对最新地图和正式地址**。以工厂最新已发布仓库地图和正式区域/货架/层格/地面货位为准。保留尚未发布的地图草稿，先报告草稿与正式状态差异，不自动用草稿覆盖正式库。比较稳定 location_id、员工地址、空间顺序、货位资格、区域策略、货架层格数量；检查是否有停用、退役、删除重建或地址变化导致的固定绑定失效。不得导入家庭端演示布局或演示货位。
2. **检查产品对应关系**。核对客户中文简称、客户存货编码、产品、整数显示尺寸、每捆数量、主位及补充位、固定集货区参考货位、已有预警策略。一个货位只绑定一个客户料号，包装未知不能猜成20只，预警未知不能猜成200只。地图只能给出位置，不能推断客户料号的固定绑定；缺少映射的项目列为待现场配置。
3. **用隔离副本验收**。在工厂数据的隔离副本演练 `rq07v8x9z66 → rs08v8x9z67`。新迁移只增加4表，无业务回填；若当前迁移链已推进，先安全衔接并验证，不覆盖现有迁移。按仓库现有发布服务读取/同步正式位置，以实际业务授权为准，不直接改SQLite表或重建占用货位。
4. **跑本次最短有效验证**。执行 `tests/test_shelf_pick_scan.py`、`tests/test_fixed_shelf.py`、`tests/test_fixed_shelf_staging.py` 和实际受影响的拿货/空间编号/标签用例。确认扫码50只只改变拿货状态，货位、可用量和预占量不变；重复扫码不累计，其他员工任务、旧标签、错误货位和多位置来源不会误记。确认选定任务不适用时不会自动切到另一张任务。
5. **验收整条操作链**。正式入库带出固定目标→实物确认上架→预送货→手机/A4→货架扫码拿齐→实际集货确认→装车发货。检查少拿差异、部分移库、退回后重新集货、取消和改明细，发货消费实际集货批次；取消不假定货物已回架。确认扫码后页面显示“已拿齐·待集货”。组合子件主品和同订单行并行拿货遵守当前候选边界，不绕过来源校验。
6. **按最新正式位置试打标签**。标签80×40mm、无外框；第一栏右侧二维码，其下分隔线；“客户：”“存货编码：”“产品名称：”“规格mm：”字段等宽对齐。规格值形如 `400x300x250`，不再带mm。客户用中文简称，客户右侧两行分别为每捆数量和预警参考。先100%实际大小打印一张并用员工实际手机扫码；核对二维码使用工厂可访问的固定局域网地址和正确端口。示例PDF只供排版预览，正式标签必须从工厂系统生成。
7. **再执行正式发布门禁**。本次允许推送代码不等于直接操作生产库。完成可审查的副本验收和接入差异报告后，按工厂已有有效发布授权范围、NAS发布规则执行验证备份、迁移、重启、健康检查与少量现场冒烟；缺少正式发布授权时仅停在发布步骤。不要从家庭端替换工厂数据库。

交付时说明：最新地图版本/正式位置数量、固定绑定有效/待配置/失效数量、处理过的实际差异、最终代码提交与迁移版本、测试和实体扫码结果、正式数据是否写入、尚需现场确认的事项。不要把源码候选、隔离副本验收和工厂已经上线混为一谈。
