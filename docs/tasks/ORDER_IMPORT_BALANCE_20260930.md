## 已给出的整体方案与事实

- 在库存/需报和异常之间添加抵扣后库存。默认显示符合当前客户/产品实物身份的成品可用余量；明确人工不抵扣时显示有效实存（含已预占、已集货）；自动因前序行耗尽而跳过不等于人工不抵扣，必须显示余量0。
- 全部新增数量保持真实物理单位；订单客户数量、材料张数沿用原合同，不能相加。提示展开显示实存/既有预占/其他不可用/导入前可用/本行拟用；不新增正式扣库动作。
- 同客户前序草稿和本草稿使用服务器同一预览请求顺序模拟，仍保留全局既有分配额度及保存前事务核验。使用请求内唯一行号避免跨文件client_line_id碰撞；旧请求不得覆盖新选择。
- API原200行安全上限保留。多单合计超过上限时余额、需报提示分批核对，不能假显示本单为全批余额；单单超过上限不发送超限请求。原服务器保存核验不放宽。
- 数量框压缩到六位整数可见，标准/大字与价格可见/隐藏都验证。无金额权限时不新增金额展示。
- 原件“包装箱格式 (1)”!O2是管理NO.:，P2底层是2026-09-30日期，Excel格式yyyymmd显示20260930。按显示格式保留订单号，兼容空格/大小写/点和冒号，保留前导零；不读取无关或隐藏说明表为订单号，不静默合并冲突编号。
- 不修改历史订单、库存、数据库结构或桌面Excel；不新增报料规则、不自动纠正客户归属。识别出的客户、交期和明细仍走现有核对。
