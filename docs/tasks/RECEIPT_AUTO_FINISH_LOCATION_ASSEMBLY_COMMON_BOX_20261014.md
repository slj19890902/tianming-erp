## 范围与优先级

本任务依据老板 2026-10-14 最新业务要求，优先于总需求中“补库必须手动加工”“BOM 必须手动组套”“自动成品默认进入一楼待送区”等旧规则。仅实施以下闭环，不重构 ERP，不扩展报价、财务、产品档案或备份系统：

1. 有明确目标产品与冻结生产资料的订单/补库来料，实收后按累计实收计算、仅记本次增量，原子完成材料消耗、成品入库和追溯；BOM 严格按冻结配方及真实可用/预占数量齐套。无明确用途的通用原纸保留原料事实，不进入日常待加工。
2. 手动组套只消费盘点或自动流程剩余的真实自由子件；订单预占子件不得重复组套；成品盘点库存不得二次组套。
3. 同一真实产品和客户归属默认沿用同一正式货位，原料/半成品/成品位置共同参与；单位、状态、批次、成本、预占与来源仍分账。未知、失效、冲突位置要求员工一次选择，不创建虚拟位、不默认一楼待送区、不自动搬迁历史实物。
4. 订单新建和送货单新建的常用箱弹窗仅调整为“勾选框 → 数量 → 编码 → 信息”，导入按钮移至左下角，保留搜索、分页、多选、数量记忆/校验和原接口语义。
5. 纯组套父件（包括 80012500 同类）不要求父件独立生产规格；必须具备真实产品身份、客户、成品单位、有效冻结 BOM，并以真实消耗子件的冻结身份、单位、配比、批次、数量、成本及资格形成组套依据。普通独立生产产品与随货配套关系仍按原规则校验。错误必须定位到具体子件和缺失项。
6. 入库完整性按操作用途统一判定：报料资料、成品规格、外购冻结规格、半成品实物资料及纯组套子件依据不得混用。产品列表只能承诺“报料资料完整”；盘点预检和提交共用入库缺项结构，错误须列出字段、来源、原因、修正入口和处理责任。82021188 为隔离必测，不设编码特例。
7. 订单报料缺口和业务状态共用正式履约覆盖：只计算已提交且仍有效的成品预占、实际送货、有效采购/实收和生产事实，已消耗、释放、取消及父子件重复来源不得重复覆盖。80020549 为隔离必测，不改历史库存、采购或送货凑显示。
8. 000120 同类盘点、历史移库、收料余件及加工产出子件，按真实批次资格进入统一组套，不得强制伪造补库加工任务。身份不全的库存必须显示具体缺口并经可审计核对后使用；尚未组套的子件只显示可组套数，不能冒充父件成品。000120 正式数量须只读按流水核定，已处理的 50 套不得重复扣减。
9. 加工记录的“当前位置”按库存当前正式位置逐批投影，支持多个可点击位置；加工时位置只作历史事实，已出库和退役位置明确标识。当前链接必须满足“库存位置 ID → 正式货位 → 正式区域 → 当前发布地图可见对象”；废弃区域按引用分级停用/清理，不得先删位置或按名称、版本批量修补。

## 成功条件与不变量

- 收料、组套、撤销、抵扣和送货数量守恒；张、只、套不混用；分批累计舍入、重复回调、并发重试只生效一次。
- 订单用途成品只增加并预占给来源订单；补库成品只增加可用库存和补库覆盖，不增加来源订单可送量。
- 未齐套子件及超收/余数保留真实库存；不得把“到过一批”当作数量齐全，不伪造整套、不丢数量。
- 收料与自动成品沿用现有一致性事务；任何失败完整回滚库存、预占、成本、组套记录和流水。
- 位置身份、已发布地图版本、可读名称、区域状态、权限和容量规则由统一正式位置服务校验；预检和提交使用同一逻辑。
- 人工拆分库存保持拆分；不能可靠识别历史拆分时只增加最小新标记，不猜测回写历史。
- 历史加工记录与未完成任务真实保留。上线前列明旧待加工数量/来源；缺完成依据的旧任务进入历史待核对，不批量改成品、不隐藏。
- 纯组套父件不填假规格，不复制任一子件规格；多级 BOM 允许中间组合节点无纸板长宽，但必须检查循环、身份、配比、数量、成本及实际来源。
- 原失败表单可安全重试；同键同载荷只成功一次，配方或库存版本变化要求刷新。
