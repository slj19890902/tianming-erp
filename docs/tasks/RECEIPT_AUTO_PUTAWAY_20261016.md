# 收料自动成品与默认位置（2026-10-16）

按已交付的《收料自动成品与默认位置-原因及优化方案》实施。正式业务源码基线 `8472f75f`，正式版本 `v0.22.649`。

验收：明确产品收料在同一事务形成增量成品或冻结 BOM 子件；纯组合父件在同一补库需求内齐套后自动组套；成品位置按产品货位、产品区域、客户区域依次选择；缺失或失效配置明确报错；不从原料暂存推断成品默认位。分批、幂等、成本、现有预占和历史数据不可重复入账。

历史修复：用户确认 80010631 的剩余实物已在 E2-1-1；仅将批次 1465 尚可用的 4430 只账面从旧位 1300 转至常用箱所设货位 1620，不重生产已消耗的 570 只。80012632、80012410、80012411 复用原待加工任务及预占；最新正式只读核验确认产品 3411 的具体货位 1638、3406 的 C 货架区域 130、3407 的 E 货架区域 128 已设置。区域配置在正式地图中选择空闲、允许成品的实际货位。所有历史业务动作须在正式备份、最新版本预检和隔离复演后分别受控提交，并核对数量、成本、来源、位置及审计。

上线影响：正式库仍有大量未设产品默认位置且客户成品区域为空的旧主档；本修复不猜填它们的位置。若这些产品发生新的明确产品收料，收料会提示先在常用箱或客户资料设置正式目的地。发布前记录当前待收业务是否涉及此类主档。

v651 补充：跨两个原料批次的累计自动完工需要在完工历史中成组显示与撤销，产出只反冲一次，两个投入批次及预占全部恢复后，方可撤销各笔收料。此边界由真实 HTTP 分批实收、完工撤销和逐笔收料撤销回归验证。
