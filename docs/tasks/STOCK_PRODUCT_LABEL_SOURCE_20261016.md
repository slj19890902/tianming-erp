# 无订单补库产品标签来源修复与 BOM 标签方案

用户范围：已正式报料且常用箱启用产品标签的明确产品，可以在报料/来料阶段打印身份与每捆数量标签，不依赖销售订单生产任务或出货。BOM 父件标签本轮先形成方案，不改组套/库存业务。

现场：明细 625（隔离快照中供应商单 211，补库明细 49）无销售订单任务；生产任务单支持补库来源，产品标签仍强制任务 FK，导致误拒绝。

实现：在原供应商报料标签入口支持真实补库来源及明确的选择键；冻结产品身份、纸板到产品单位换算、当前标签开关/每捆量、来源状态/版本与标签布局。兼容同单订单/补库混选、打印张数选择、准备/确认/补打和幂等。禁止伪造订单/生产任务；打印只新增打印作业与审计，不改变报料、收料、库存、任务状态。无产品用途通用片料不得伪造成某产品。

保护：权限和客户范围、冻结历史打印、源失效/改量/标签配置变化拒绝旧草稿、采购张数不当产品数、混选无效产品整批提示、既有订单产品标签及补库实际来料标签。

验证：先复现补库无任务失败；单品、BOM 子件冻结换算、混合来源、张数选择、重复请求、确认/历史补打、跨客户/失效/篡改以及业务表无写入。定向测试与差异检查后提交。延续当前隔离候选分支，正式发布仍受串行发布与现场门禁控制。

开发结果：现场隔离快照复现原错误；明细625关联补库49、来料524和已完成补库加工记录15（585张→2340只），不存在销售订单生产任务是正常来源类型。修复后预览生成47张（46张×50只＋1张×40只），报料行筛选和打印来源键筛选指纹相同。66项核心定向回归通过；另有4项旧前端断言通过、2项既有文案断言失败（仍期待固定“每张标签代表只数”，正式源码已用按单位变化的提示，相关文件本轮未改）。Python/前端语法、差异检查通过，Alembic保持单头eq1015sa；无迁移、无正式数据写入。父件整套标签仍仅为以下方案。

## BOM 父件提前贴标方案（设计建议，未实施）

标签来源与库存入账分开。父件不报料并不意味着父件不能有产品标签；其合法来源是已冻结的组套需求、父产品和 BOM 配方。不能要求它拥有纸板报料尺寸或销售生产任务。

| 阶段 | 可打印内容 | 默认数量与使用 |
|---|---|---|
| 子件已报料 | 子件实物标签；另提供“预打整套标签” | 子件按自身冻结产品数量和每捆量；父件按本次冻结组套需求与父件每捆套数，优先预打整捆标签 |
| 子件来料/加工后分存 | 子件标签 | 清楚标本体、补强板等实物角色；不能把未配齐子件标成整套 |
| 实物成套并入库 | 使用已预打的父件标签；不足可补打，尾捆按实际套数打印 | 成套入库时即可贴标，长期库存不用等送货；已有自动组套流程继续按真实子件消耗入账 |
| 出货 | 只补打丢失、损坏或重新分捆所需标签 | 不把出货作为首次打印的前提 |

示例：80012500 的父件、本体、补强板是三个不同产品 ID，但共用存货编码。BOM 标签应在编码下加短身份“整套 / 本体 / 补强板”，数量分别显示“50 套/捆”或“50 只/捆”；单靠相同编码无法区分。父件无独立规格时使用“整套”与必要配方摘要，不填子件尺寸冒充父件规格。普通产品现有版式不在本方案中变更。

以冻结配方每套本体 1 只、补强板 1 只为例，计划 2340 套、50 套/捆，可先打印 46 张整捆标签；预计尾捆 40 套，在实际尾捆数量确定时打印。未成套部分仍用子件标签，不因预打印标签提前写父件库存。

同一组套需求的父标签只形成一份打印计划：按真实需求 ID、父产品 ID 和冻结 BOM 版本去重，不能仅按相同配方指纹合并不同批次，也不能在每张子件供应商单各生成一遍父标签。报料页、来料页、成套库存页进入同一计划，记录已打印/本次打印/补打。重复补打沿用现有一次确认，准备后的来源变化拒绝旧草稿，实际已打印的历史冻结内容保留。

若尚无有效父件或冻结配方，提示明确缺项；不能通过任意选择同编码产品推断父件。后续实施需覆盖订单与无订单补库、分批来料、不同供应商子件、部分组套、共用编码、余片、撤销与打印重放；打印操作自身不消耗子件或生成库存。
