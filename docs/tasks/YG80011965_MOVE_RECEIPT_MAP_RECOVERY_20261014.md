# 研光转成品移货与正式地图库位恢复（2026-10-14）

现场问题：员工将 80011965 的已加工半成品转成品后，仓库部分移货报“半成品转成品来源不唯一”；所有新待入库勾选灰色，明示一楼 RAW-002/003/005/006 的区域发布版本不等于当前运行地图；加工记录地图也不能点选实际货位；C 模具架仍报原归档快照变化。

本轮代码最小闭环：转成品的成品批次拆分移货时，沿唯一真实 `InventoryLotTransfer` 和成对库存流水回溯原转换命令；验证客户、产品、实物身份、成本快照及数量。无边或损坏边拒绝。既有转换、库存数量、预占、送货、地图文件和其他成本来源不回写。无 DDL。

正式地图事实：v0.22.630 已发布程序，但正式发布回执 `business_corrected=false`、`business_deferred_reason=live-delivery-state-changed`；有限地图恢复虽经隔离副本演练，不能据代码存在或旧演练宣称正式绑定已恢复。正式库须另做只读现状核对；若原 `map_binding_audit_recovery_20261014` 的真实文件、23 区策略、审计、草稿和空间证据仍严格匹配，才在现有已验证本地备份基础上受控应用，并核对待入库和加工候选。C 架失败先核对正式/草稿归档身份及错误回执，不自动覆盖草稿或实物位置。

成功条件：部分及连续移货后成本来源仍唯一且数量守恒，同键重放无增量，损坏移货边拒绝；正式待入库可选真实已发布货位，未发布位置仍拒绝；加工地图候选与正式货位 ID 一致；C 架原因有正式证据，若不满足同一数据恢复条件则单独定点修复，不混入库存修复。

技术发布仅采用签名包与已验证的一份本地备份，不调用 NAS 备份，不自动点击正式业务页面。正式动作失败保留 ERP 服务与现场；管理员人工验收另记。
