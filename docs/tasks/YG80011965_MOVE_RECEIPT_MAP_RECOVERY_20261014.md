# 研光转成品移货与正式地图库位恢复（2026-10-14）

现场问题：员工将 80011965 的已加工半成品转成品后，仓库部分移货报“半成品转成品来源不唯一”；所有新待入库勾选灰色，明示一楼 RAW-002/003/005/006 的区域发布版本不等于当前运行地图；加工记录地图也不能点选实际货位；C 模具架仍报原归档快照变化。

本轮代码最小闭环：转成品的成品批次拆分移货时，沿唯一真实 `InventoryLotTransfer` 和成对库存流水回溯原转换命令；验证客户、产品、实物身份、成本快照及数量。无边或损坏边拒绝。既有转换、库存数量、预占、送货、地图文件和其他成本来源不回写。无 DDL。

正式地图事实：v0.22.630 已发布程序，但正式发布回执 `business_corrected=false`、`business_deferred_reason=live-delivery-state-changed`；有限地图恢复并未正式执行。2026-10-14 只读核对确认运行地图 SHA `cef9dfd43e8ef2b4d94abdd43c50e631d548e5f02a447041c996709832e1ab1b`，一楼 23 项区域绑定仍为旧版 `12069ae4137257d6`，RAW-002/003/005/006 分别有 8/12/8/2 个活动待入库位，但全部被旧绑定拦截。正式草稿相对原审核草稿只改了 C 架三格别名、版本/时间和五条保存回执；最新草稿 SHA `ec7e2cacf1959398898d98a979d9a14278b7da6af739b51ec5a49342353b6356`，仍以当前运行地图为基底。有限恢复服务只新增这一精确草稿 SHA 的允许值并二次核对基底，预览回执绑定实际草稿 SHA；若现场再变，拒绝执行。隔离测试确认不改地图文件和库存。

C 架事实：正式地图仍保存同一 ID 的已归档货架，草稿恢复后的 C 架为同一 ID；归档快照仅 `retired_at` 微秒差。当前线上 v0.22.633 已含这一个字段的容差处理，原审核地图副本上的完整单架隔离应用可通过。因此不能把旧错误提示直接当作本版仍缺少代码修复；发布后还需基于最新草稿做真实只读/隔离重放，并由管理员在页面验收。不得自动发布 C 架草稿。

成功条件：部分及连续移货后成本来源仍唯一且数量守恒，同键重放无增量，损坏移货边拒绝；正式待入库可选真实已发布货位，未发布位置仍拒绝；加工地图候选与正式货位 ID 一致；C 架原因有正式证据，若不满足同一数据恢复条件则单独定点修复，不混入库存修复。

技术发布仅采用签名包与已验证的一份本地备份，不调用 NAS 备份，不自动点击正式业务页面。正式动作失败保留 ERP 服务与现场；管理员人工验收另记。
