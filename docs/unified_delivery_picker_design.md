# 送货统一选货设计与验证
依据老板2026-09-12两张新增送货单截图。截图呈现：两个来源入口及不同列排列打断选货；车号与空提醒占据首屏；复选框小且库存数量输入禁用，增加操作。不能据截图声明完整交互或无障碍验收。
流程：1选择客户及客户范围；2统一列表搜索/分页选货和数量；3导入后统一核对明细；4原保存/打印流程。
布局：移除两类来源按钮、车号；空提醒隐藏，有提醒保持原查看处理流程。编码加粗，产品、规格、材质、订单/客户单号、库存位置、待送/可用数、本次数量依次排列。绿色订单号/黄色无订单同时有文字区分，不只依靠颜色。宽表横向滚动。
客户名单仍由原有有订单/有库存勾选筛选；列表在选定客户内展示两类来源，全局订单在前。查询与分页由新selection-items入口统一，订单资格/客户范围与库存冻结、预占、专属归属沿用原服务。
选择：普通行点击切换，复选框停止冒泡，数量点击/聚焦只选中不切换；数量input更新，重复聚焦保留值。常用箱相同，支持空格键行选择及可聚焦输入。
已选明细仍按订单/库存各自来源提交，保留补量优先、超送权限、数量审计、幂等与事务；不合并正式来源事实。
验证：后端3项(分页边界1/2/3行、订单优先搜索、来源排除、订单补量门禁、混合发货撤销原子性)；客户候选前端6项；Node3项(两类行选择/数量，常用箱，同页Vue模板和JS编译)。未做正式页面自动点击，交管理员验收。
环境：D盘满导致旧D工作树测试文件写入中断；转C盘独立clone继续，原测试已恢复。清理构建缓存的自动执行被策略拒绝，未执行；稍后观察D盘恢复约9GB。代码未因磁盘问题提前发布。
