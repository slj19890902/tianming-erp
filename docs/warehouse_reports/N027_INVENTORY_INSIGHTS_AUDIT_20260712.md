## 1. 结论先行

N-027 目前不能直接给出“仓库占用了多少现金”的可信数字。

原因不是缺少 AI，而是正式库中尚未形成完整库存事实账，并且库存批次没有可靠的实际单位成本快照：

- 正式库只有 1 个成品库存批次，当前可用量为 0，100 个已全部报废。
- 正式库半成品库存批次为 0，库存预占记录为 0。
- 3295 个有效常用箱中，`cost_unit_price` 有效覆盖为 0%。
- 382 个有效材质都有当前平方报价，但“当前报价”不是该批库存实际采购/生产成本，不能冒充历史现金占用。
- 代码已经具备批次、库位、数量、预占、冻结、报损、流水和库龄基础，可以先做确定性看板和数据质量提醒。

因此建议按以下顺序推进：

1. 先上线不依赖成本的确定性看板：数量、库位、库龄、最后异动、预占、近 30/90/180 天需求、需求覆盖和成本待补。
2. 再新增库存批次成本快照，所有历史缺失成本必须显示“成本待补”，不能按 0 元计算。
3. 完成三楼盘点和连续 3～6 个月流水后，再让 AI 解释积压原因和提出采购上限建议。
4. AI 只能建议，不能自动修改采购数量、库存、预占、报损或订单。

## 4. 第一版确定性看板口径

### 4.1 顶部必须先显示数据可信度

看板顶部固定显示：

- 已盘点库存批次数 / 预计现场批次数
- 有库位批次占比
- 有成本批次占比
- 近 30 天有流水批次占比
- 正式库迁移是否达到当前代码 head

数据不完整时必须显示“当前仅代表已录入库存”，不能让用户误以为覆盖了 1400～1500㎡现场库存。

### 4.2 库龄分组

- 0～90 天：正常
- 91～180 天：关注
- 181～365 天：慢动
- 366～548 天：超过 1 年
- 549～730 天：超过 1.5 年
- 731 天以上：清理候选

库龄严格以 `stock_date` 为准；最后异动不重置库龄。看板另行显示 `last_movement_at` 和 `movement_stagnant_days`，用于说明停滞情况；若最后异动时间缺失，停滞天数显示为待补而不推断。

### 4.3 成品库存需求覆盖

按客户 + 存货编码 / 产品统计：

- 当前可用量、预占量、冻结量
- 当前未完成订单需求
- 近 30/90/180 天订单需求
- 可覆盖订单数量
- 库位列表
- 最近一次入库、预占、消耗时间

“先使用库存”建议只在同客户同产品或已确认通用关系下出现，并继续要求人工确认。

### 4.4 半成品可复用库存

按已经确认的业务规则检查：

- 楞型必须相同
- 库存片料长宽必须覆盖需求尺寸
- 毛料/净片/已有压线按既有兼容规则判断
- 材质不同或已有压线时给出醒目警告
- 人工确认过的产品分配和匹配规则优先

看板显示候选批次、库位、可抵扣张数、尺寸余量和警告原因；不能自动预占或自动减少采购。

### 4.5 行动队列

第一版至少包含：

1. 有库存但 180 天无需求。
2. 超过 1 年仍有可用量。
3. 缺少库位。
4. 缺少成本。
5. 有订单需求且存在可用成品库存。
6. 有待报料需求且存在可复用半成品库存。
7. 冻结、破损或报废数量长期未处理。

## 5. 成本数据建议

推荐后续在库存批次保存两套不可混淆的成本快照：

- `actual_unit_cost_snapshot`：实际采购/生产入库单位成本，可为空。
- `estimated_unit_cost_snapshot`：按当时材质报价和产品公式形成的估算单位成本，可为空。
- `cost_source`：实际采购、实际生产、产品成本、材质估算、人工补录等来源。
- `cost_recorded_at`：成本形成时间。

规则：

- 实际现金占用只使用实际成本。
- 实际成本缺失时显示“实际成本待补”。
- 估算金额必须明确标注“估算”，不能混入实际金额合计。
- 历史批次不批量填 0，也不使用当前售价反推成本。
- 成本变更必须留审计记录，不覆盖原始库存流水。

这一步需要 Alembic migration；必须先在正式库副本升级/回退演练，再单独申请正式迁移批准。

## 6. 分阶段实施建议

### Phase A：无迁移确定性看板

- 新增只读库存洞察 API 和页面。
- 显示数量、库龄、最后异动、库位、需求覆盖、半成品可复用候选。
- 所有金额显示“成本待补”，不输出虚假 0 元。
- 所有建议只读，不自动预占、不改报料、不改订单。

### Phase B：成本事实账

- 新增实际/估算成本快照字段和来源。
- 手工入库、补库入库和采购入库时保存成本来源。
- 旧批次保持空值，由人工盘点时补充。
- 副本 migration 往返演练和数据质量测试通过后，再申请正式迁移。

### Phase C：三楼小范围实盘

- 先录 3～5 个成品栈板和 2～3 个半成品栈板。
- 验证库位提示、库存数量、成本录入、订单需求和抵扣推荐。
- 通过后再逐区盘点，不直接批量导入整仓。

### Phase D：AI 解释与采购建议

只有连续 3～6 个月真实流水、成本和需求数据达到可信标准后才进入：

- 解释库存为何堆积。
- 给出清库优先级。
- 建议采购上限或暂缓采购。
- 预测库存可能占用的仓库空间和现金。

AI 结果必须显示依据，并由人工决定；不得自动执行。

## 7. 当前闸门

进入 Phase A 编码不需要数据库迁移，可以直接做只读看板。  
进入 Phase B 前需要用户确认成本口径，并批准新增 migration 在数据库副本演练：

1. 实际现金占用以“实际采购/生产入库成本”为准。
2. 当前材质报价计算值只作为“估算库存价值”。
3. 两种金额分开展示，不合并成一个数字。
