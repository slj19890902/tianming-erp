# 工厂数字孪生布局编辑器 MVP · Phase 2A

这是一个与正式 ERP 数据隔离的 React + Three.js / FastAPI 子应用。Phase 2A 在 DXF 底图和人工设备布局之上增加货架、堆放区域、通道、禁放区、图层与简单规则检查，不读写库存、订单、生产、流水或正式库位数据。

## 本地运行

```powershell
$env:FACTORY_TWIN_EDITOR_TOKEN='local-mvp-token'
python -m factory_twin.backend
```

另开一个 PowerShell：

```powershell
Set-Location factory_twin\frontend
npm install
npm run dev
```

打开 `http://127.0.0.1:5174`。后端默认监听 `127.0.0.1:8092`，开发数据库为 `factory_twin/data/factory_twin.sqlite3`。

如需读取另一份已授权的 ERP 隔离副本，可在启动后端前显式指定只读源：

```powershell
$env:FACTORY_TWIN_ERP_READONLY_DB='D:\tm-uat\your-approved-copy\carton_erp.sqlite3'
python -m factory_twin.backend
```

连接使用 SQLite `mode=ro` 和 `PRAGMA query_only=ON`；路径未配置时默认读取当前项目 `data/carton_erp.sqlite3`。不要把生产机正式数据库复制或替换到数字孪生目录。

## Phase 2A 功能

- 设备可“确认并锁定”，锁定后后端拒绝移动、旋转、改尺寸和删除。
- 参数化货架支持毫米长宽高、层数、格数、正面方向、最小通道宽度和 90° 旋转。
- 区域、通道和禁放区使用毫米坐标点保存；2D 与 2.5D 共用同一数据源。
- 区域支持“地面堆放 / 货架上层 / 架空共享”垂直语义。货架上层区域可与下方设备共享平面投影，只有真实高度区间相交时才报冲突；2.5D 会按离地高度显示立体存放层。
- 同一布局重复绘制时会按类型自动生成下一个可用编号，例如 `ZONE-1F-RAW-001` 后自动使用 `ZONE-1F-RAW-002`，不会覆盖既有对象。
- AI 来源的对象只能创建为 `candidate`，必须通过人工确认接口才能成为 `confirmed`。
- 简单规则检查覆盖货架占通道、堆放区压设备/柱子、通道宽度不足和消防出口遮挡。
- 内置模拟纸箱厂底图、三台生产设备、模具货架、堆放区、叉车通道和消防出口禁放区。

## Phase 2B-1 工业可视化

- 2D 工业平面使用墙柱实体、区域斜纹、禁放区交叉纹、通道方向箭头、设备名称、比例尺、图纸北向和实时毫米坐标。
- 两点测距只在浏览器内计算并显示毫米/米，不保存或修改布局对象。
- 2.5D 按设备名称和素材分类生成印刷、模切、成型、输送及通用设备的轻量参数化外形；尺寸仍来自原设备记录。
- 货架以立柱、横梁、层板和格位显示，并显示单面/双面操作方向；货架上层区域继续按离地高度显示。
- 支持东北、西北、东南、西南固定等距视角及一键全图适配。
- “导出 PNG”保存当前画面；“A3 / PDF”调用 A3 横向打印样式，可在系统打印窗口另存为 PDF。两项操作均不写业务数据。
- 主工作区固定为一屏，左右面板独立滚动，适合 1366px 及以上办公室显示器。
- 相机视角在选中对象、增加绘制点和切换图层后保持不变；只有切换 2D/2.5D、选择固定视角或点击“全图适配”才重置。
- 2.5D 左键拖动用于旋转观察，右键/中键用于平移；设备和货架的位置调整集中在 2D，避免误拖与视角旋转冲突。

## Phase 2C-1 一楼真实生产周转只读投影

- 一楼右侧新增“真实生产周转”面板，只读读取 ERP 中当前 `pending` 生产任务的任务号、订单、客户、产品、计划数量、正式状态和更新时间。
- 未定位任务只进入“待定位”列表，系统不会自动猜测坐标、自动占用栈板或改变既有设备与布局。
- 管理员可把任务人工关联到当前一楼已有栈板或区域；隔离数字孪生库只保存 `erp_production_task + source_task_id + target + confirmed_at + version`，不复制正式数量账。
- 已人工定位任务在 2D/2.5D 使用同一青色信标；图层“生产任务投影”可独立开关。
- ERP 任务离开待生产清单后，不再作为当前事实显示；旧定位进入失效提示，避免把已完成或已删除任务静默保留在地图。
- 地图没有生产确认、完工、入库、移库、送货或库存调整入口。正式生产、订单和库存事实继续由 ERP 权威服务管理。

## 人工墙体、卷帘门和窗校正

- “墙/门/窗”工具可绘制简易墙体、卷帘门和窗，统一保存毫米坐标、厚度和高度。
- 墙体支持连续取点；卷帘门和窗点击两个点确定位置与方向，再按输入的实际净宽生成，因此不再使用固定 1000 mm 门宽。
- 窗可设置窗台离地高度，2D 与 2.5D 使用同一组端点和尺寸。
- DXF 识别出的墙、柱、门可点击查看源句柄。误识别对象通过 `dxf_hidden` 候选隐藏，不删除或改写 DXF；删除该候选即可恢复。
- 缺失的卷帘门或窗使用人工结构补画，状态仍为候选，须人工确认后保存为已确认对象。

## 三楼实测图与旧 ERP 区域候选

- 三楼扫描 DXF 以米为输入单位，导入后统一转换为毫米；当前源图识别为 17 组墙、8 个门和 11 个窗。
- DXF 门窗块会保留可解析的实际开口宽度，不再只显示固定尺寸标记。
- `factory_twin.scripts.plan_floor3_overlay` 只读核对旧三楼隔离数据库的 22 个区域、398 个布局记录和 revision，再把 A1～F34 作为 AI 候选套准到实测平面。
- 老板已确认 F 区位于上下两块建筑之间；二次套准以实际 DXF 墙线为锚点，将 F 放入连接带，并将 A～E 下移到主大厅。现场再次纠正方向后，A～E 保持主通道两侧的 1/2 列关系，只沿主通道方向执行上下镜像，使区域顺序由上到下变为 E、D、C、B、A。
- 候选套准只生成区域轮廓和旧主通道，不生成 398 个正式库位，也不复制库存、栈板数量或设备。
- 半成品/原料侧因现场没有地线，仅显示共同待规划范围，不猜测内部划分线。
- 再次导入同一 DXF 会刷新只读派生墙门窗，并保留已经绘制的区域、货架和候选对象。

只读干跑：

```powershell
python -m factory_twin.scripts.plan_floor3_overlay `
  --dxf "D:\Downloads\My New Project - 3rd Floor.dxf" `
  --legacy-db "D:\tm-uat\p0-floor3-compat-ledger-20260726\carton_erp_cr74_browser_uat.sqlite3"
```

对首次导入、仍未人工修改的 AI 候选执行二次套准：

```powershell
python -m factory_twin.scripts.plan_floor3_overlay `
  --dxf "D:\Downloads\My New Project - 3rd Floor.dxf" `
  --legacy-db "D:\tm-uat\p0-floor3-compat-ledger-20260726\carton_erp_cr74_browser_uat.sqlite3" `
  --apply --recalibrate-existing --confirm "RECALIBRATE 3F CANDIDATE"
```

二次套准只更新坐标仍等于首次导入值的 AI 候选。对象一旦被人工确认或手工改过坐标，脚本会在写入前整体停止，避免覆盖现场调整。

区域、通道、禁放区和人工补录的墙门窗柱可在 2D 视图中直接按住拖动。拖动是毫米坐标的整体平移；松开后才通过版本门禁保存，并自动回到待人工确认状态。DXF 原始结构继续锁定且不可拖动。

选中区域后，右侧“区域长宽与位置”可直接输入中心 X/Y 和 X/Y 方向真实尺寸，也可按 100mm 步长微调。区域按当前外包框缩放，编号和顶点顺序不变。人工门窗柱可在创建前输入净宽/柱宽、厚度/柱深和高度，创建后仍可调整尺寸；柱编号使用 `COL-楼层-001...`。

货梯使用跨楼层连接编号 `LIFT-001...`。在 1F 和 3F 分别用同一编号绘制货梯投影，两个投影的位置和方向各自独立，用于对准两张楼层图；选中任一投影修改货梯长、宽、高时，会按版本门禁同步到当前已找到的同编号楼层投影，但不会自动平移楼层、区域或设备。另一层尚未绘制同编号货梯时，属性栏明确显示“尚未连接”。

老板已确认1F原 `LIFT-003` 与3F `LIFT-002` 为同一台货梯；当前统一使用 `LIFT-002`，一楼候选投影精确采用三楼实测中心、轮廓方向、约2000mm线段长度、3000mm深度和3500mm高度，三楼权威对象保持不动。

## 三楼区域语义与柱网优化

- 三楼没有正式“成品待送区”时，送货余数使用独立的“送货余数暂存”语义，不再混入正式待送流程。
- 区域用途增加“地线分区（用途待确认）”“货架存放”“待确认存放”，用来保留现场几何但避免过早宣称库存用途。
- 选中区域后可直接修改用途和名称；修改不会移动多边形或更改库存，保存后仍为候选。
- `optimize_floor3_layout.py` 默认只读预演。它只对现有候选做两类最小修改：按当前同行/同列的中位线对齐人工柱心并正交柱体；把错误的三楼成品待送语义改为余数、货架、地线待确认或待确认存放。
- 优化脚本不新增、删除或重编号柱子，不改变柱宽柱深，不移动墙体、通道、区域、货架或货梯；应用前输出可恢复的三楼 JSON 快照。

只读预演：

```powershell
python factory_twin/scripts/optimize_floor3_layout.py `
  --layout-id edfd9fd4-f013-41cf-b491-cd9d5dce6f52
```

应用到候选布局：

```powershell
python factory_twin/scripts/optimize_floor3_layout.py `
  --layout-id edfd9fd4-f013-41cf-b491-cd9d5dce6f52 `
  --apply
```

## 三楼现场确认后的运营候选

- 三楼通道不是特种设备叉车通道，而是人员与手动液压搬运车共用：主通道真实宽度1900mm，次通道1500mm，双向且禁止堆货。
- A～E地线区使用“成品存放”语义，允许现场临时混放少量半成品或原料，但不等于正式成品待送区。
- FIN-001、FIN-002已按老板确认释放为空地；送货余数只保留FIN-003～005三个墙边候选区。
- D1/D2编号按现场交换：北侧无货架区域为D1成品存放区，南侧为D2货架区；D2北端预留3500mm空地。
- F区从西向东保持F1、F2、F3、F4；F1扩为2200mm双排1100mm货架，F12/F34按相邻货架重新交换到正确间隔。
- 参数化货架使用“地面栈板+上方两层”的三级显示；2.5D增加木托盘、纸箱货物、立柱横梁和操作面箭头。
- 当前三楼保持17个独立货架：D2 5个、F1 4个（两排各2个）、F2 2个、F3 2个、F4 4个；少数货架长宽仍可按现场复测调整。
- D1为无货架栈板成品区；D2为以货架存储为主、允许栈板混合存放的地面区域。
- `ZONE-3F-FG-001`、`ZONE-3F-FIN-003`、`ZONE-3F-FIN-004`统一为送剩零头纸箱长期存放区，等待同订单续配，不作为普通成品仓自动分配。
- 根据7个DXF门洞和LIFT-002货梯门生成8个禁放区候选；检测到的压门冲突只红色提示，不自动移动现有区域。

这组已确认规则的脚本默认只读预演：

```powershell
python factory_twin/scripts/finalize_floor3_operational_plan.py
```

只有带 `--apply` 才写入数字孪生候选数据库，并在写入前输出完整三楼JSON快照。

## 标准栈板自由组合与智能吸附

- 左侧“标准栈板 · 自由组合”默认提供1200×1000×150mm木质栈板，单个对象可以修改长宽高、木色、毫米坐标并旋转90°。
- 在2D视图中自由拖动；进入180mm默认阈值时吸附到可存放区域边线、相邻栈板边线或中心轴，并显示青色辅助线。距离较远时保留人工坐标，也可关闭智能吸附。
- 后端在创建、拖动、旋转和改尺寸时再次执行权威校验：栈板必须完整位于地面可存放区域，不得重叠其他栈板，不得压设备、柱子、通道、禁放区或实体人工结构。
- 按现场规则允许栈板位于货架下方；栈板不绑定ERP正式库存、不生成正式库位，也不推导库存容量。
- 栈板在2D和2.5D共用同一数据；2.5D使用轻量木质层板、纵梁和脚墩显示，刷新后坐标和尺寸保持。

## 数据边界

- DXF 原文件只在单次请求中只读解析，解析后临时文件立即删除。
- 数据库只保存源文件名、SHA-256、派生结构、设备/货架素材元数据、布局坐标和候选/确认状态。
- 外墙、墙体和柱子标记为锁定；所有 DXF 结构都没有修改接口。
- 旋转角度只允许 0/90/180/270，坐标和尺寸统一为毫米。
- 货架上层的离地高度和占用高度必须按现场实测录入；界面给出的 2500 mm 只是录入起点，不是照片推算结果。
- 默认编辑令牌仅用于本机 MVP；部署或接入 ERP 前必须改为正式登录、角色和审计门禁。
