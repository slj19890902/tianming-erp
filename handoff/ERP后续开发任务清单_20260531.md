# ERP 后续开发任务清单

交接日期：2026-05-31

## P0：先保证架构正确

1. 在服务器或极空间 NAS 上正式运行 ERP。
2. 电脑只浏览器访问，不保存正式数据库。
3. 修改默认密码。
4. 建立数据库自动备份。
5. 确认 NAS/服务器固定 IP 和访问端口。
6. 确认 `carton_erp.sqlite3` 持久化在服务端数据盘。

## P0：防崩溃与分页

必须优先做：

1. 所有列表接口增加分页参数：`page`、`page_size`。
2. 所有查询接口默认 `page_size <= 100`。
3. 订单、历史订单、订单明细、产品档案、文件索引都必须点查询或刷新后加载。
4. 历史订单不允许无条件查询全部。
5. 客户款号改成远程搜索，不要一次加载所有款号到下拉框。
6. 大数据表加索引。

建议索引：

- `legacy_ruida_orders(customer_id)`
- `legacy_ruida_orders(source_updated_at)`
- `legacy_ruida_order_items(customer_id)`
- `legacy_ruida_order_items(style_no)`
- `legacy_ruida_order_items(customer_order_no)`
- `legacy_ruida_order_items(legacy_order_id)`
- `product_archives(customer_id, style_no)`
- `company_file_index(customer_id, category)`

## P1：客户产品档案

目标：

把瑞达历史款号真正变成新 ERP 的核心资产。

需要做：

1. 客户产品档案页面。
2. 按客户、款号、客户单号、材质查询。
3. 展示规格、材质、箱型、工艺、历史价格、供方、备注。
4. 一键带入新订单。
5. 支持客户重复档案合并。
6. 支持从历史订单反查最近成交记录。

## P1：历史订单查询

数据源：

- `legacy_ruida_orders`
- `legacy_ruida_order_items`

需要做：

1. 历史订单查询页面。
2. 按客户、日期、款号、客户单号、电脑单号查询。
3. 先显示订单主表，点开后再查订单明细。
4. 明细必须分页或懒加载。
5. 支持把历史订单复制为新订单。

## P1：报材料/采购

需要做：

1. 按订单生成报材料单。
2. 选择供应商。
3. 保存纸长、纸宽、材质、数量、采购单价。
4. 跟踪状态：待报材料、已报材料、纸板已到。
5. 纸板到料后提醒车间生产。

## P1：送货回签

需要做：

1. 按客户生成送货单。
2. 同一客户多订单合并送货。
3. 打印送货单。
4. 上传或关联回单照片。
5. 未回签提醒。
6. 回签后转应收。

## P1：应收对账

需要做：

1. 按客户、月份生成对账单。
2. 已送货未对账。
3. 已对账未收款。
4. 收款登记。
5. 开票状态。
6. 导出 Excel。

## P1：客户资料索引

数据源：

- `company_file_index`

需要做：

1. 客户资料索引页面。
2. 按客户、文件类型、关键词查询。
3. 展示文件路径、修改时间、大小、分类。
4. 支持复制路径。
5. 如果服务端能访问共享路径，再做在线打开文件。

## P2：权限和审计

当前只有：

- boss
- workshop

后续建议：

1. 修改密码功能。
2. 用户禁用。
3. 操作日志。
4. 老板端可看金额。
5. 车间端不显示价格、利润、财务数据。

当前不做：

- 计件工资

## P2：数据库升级建议

当前 SQLite 可用，但如果多人频繁同时写入，建议升级：

- PostgreSQL
- MariaDB

如果升级数据库，应迁移：

- customers
- suppliers
- product_archives
- orders
- deliveries
- accounts_receivable
- company_file_index
- legacy_ruida_customers
- legacy_ruida_orders
- legacy_ruida_order_items

不建议长期在 NAS 共享盘上让多个后端同时读写同一个 SQLite 文件。

## P2：备份策略

建议：

1. 每天自动备份 SQLite。
2. 每周保留一个周备份。
3. 每月保留一个月备份。
4. 备份文件至少保存在两个位置。
5. 定期做恢复演练。

## 最重要的开发原则

1. 不自动加载大表。
2. 查询必须分页。
3. 历史数据和当前业务数据分开。
4. 客户是中心。
5. 款号/产品档案是复用核心。
6. 车间端只展示生产必要信息。
7. 业务文件保留路径索引，不把大文件直接塞数据库。
