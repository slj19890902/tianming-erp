## API 与会话前提

`src/api/client.ts` 会携带 Cookie，但当前默认 API 地址仍拼接当前主机的 8002 端口。
这只是该分支的旧开发假设，不能代表工厂当前受管入口。预览时必须通过
`VITE_API_BASE` 明确指向隔离后端，并确认：

1. 后端实例使用临时 SQLite，不引用任何正式库或正式库副本的可写路径；
2. 配置目录、上传目录、导出目录和备份目录均在临时根目录；
3. 邮件抓取、PDF 后台识别、供应商结算、打印及其他定时任务全部关闭或替换为假实现；
4. Cookie Secure/SameSite、CORS、TrustedHost 和代理头与所测 HTTP/HTTPS 模式一致；
5. 不向正式端口发送任何写请求。

仅启动第二个端口不构成隔离。

## 预览边界

隔离后端就绪后，才能在仅本机绑定的前端开发服务中预览：

```powershell
$env:VITE_API_BASE='http://127.0.0.1:<隔离后端端口>'
npm run dev -- --host 127.0.0.1 --port <隔离前端端口>
```

上述环境变量只在该次 PowerShell 进程内使用。预览结束后删除临时数据库、上传与
导出目录前，应先确认其绝对路径位于隔离根目录。

## 上线前必须完成的业务验收

以下项目必须基于隔离数据逐项验证，并由管理员在正式页面发布后人工复核；不能用
“10 个页面无 404”代替：

- 登录、`/me`、退出、会话过期和四角色权限；
- 实际接单与订单明细；
- 报料、供应商排单、来料确认与撤销；
- 车间拿货和二维码授权流程；
- 送货单、回单、对账和收款；
- 库存数量、货位、状态和历史；
- 报料单、送货单、标签等实际打印版式及实物打印。

在这些验收、依赖风险和 API 入口适配完成前，禁止覆盖生产静态资源或替换正式首页。
