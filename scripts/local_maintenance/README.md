# 本机存储维护（ERP 外部固定范围任务）

授权与频率：2026-10-17，完整 `.tmbackup` 仅发布/迁移前生成。日常在线 SQLite 快照每15分钟，保留最近3份；非数据库业务文件及配置以加密内容寻址对象按变化备份，绑定每一份数据库快照。无NAS，不更换正式程序、schema、业务配置或启动监督器。

## 安装与运行

源码入口 `install.py` 本身不能直接安装：须把全部维护资产SHA-256固化到 `PINS`，审核该安装脚本，再通过现有系统管理员授权运行。资产安装到 `/Library/TianmingERP-LocalMaintenance`，root所有、普通账号不可写；没有通用免密sudo。`launcher.py` 只接受 cleanup、backup、verify-pair、close-readback 固定动作，验证资产和实际当前签名运行依赖，不执行开发工作区代码。

- `cn.tianming.erp.local-maintenance`：每小时检查（启动后亦检查）。原生维护锁或发布锁忙则退出75，由launchd间隔300秒重试；成功后仍按每小时检查。空间下限200GB。
- `cn.tianming.erp.online-backup`：每15分钟检查。使用专用服务身份499及已存在钥匙串授权，在原生维护锁内执行在线备份；不停服。
- 每次随实际当前程序选择相应受保护运行依赖；状态或进程变化即终止当次回收。更新到不支持这些API的程序时失败关闭，在状态文件明确报错，不能换用未验证开发运行环境。
- 旧监督器使用不兼容备份模块。必须先通过实际新点和隔离恢复，才写原生支持的 `automatic-backup-paused.json` 停用旧每日定时器。此门禁不撤销发布或迁移前的显式完整备份。

## 回收边界

实时保护 current、previous、schema、migration、restored角色、运行进程、系统启动辅助工具、活动任务、数据库路径引用和保留恢复点的程序绑定。签名回退链保护完整签名原包；仅有传递回退关系、没有上述实际角色或开发环境引用的旧展开目录/缓存，可以在原包与每个文件完整校验后回收，需要时从保留原包重建。开发venv元数据和浅层符号链接逐次核对，不跟随挂载链接；未知备份绑定仍保护所有可能程序。不能仅凭文件年代或“已发布”推断完成。

交付产物回收要求原生结构化 `technical_release_complete` 回执、签名与源码提交、精确副本/成员校验、没有路径/进程/业务依赖、独立构建空闲检查及至少1小时宽限。历史展开代码还可按另一条已授权条件回收：另有完整签名校验原包、源码提交仍在、展开逐文件校验一致且没有运行/恢复/活动候选引用；未交付的活动候选仍单独保护。实际范围：

1. `builds/*/release.signed.zip`、`.unsigned.zip`、`.signed.zip.pending` 中已完成交付的精确重复副本；签名原件必须仍完整，额外未知成员保护。只以开发UID501删除，不删源码、签名清单或任务证据。
2. 直接 `/Library/TianmingERP-*/` 下经上述验证的重复发布中间ZIP。
3. 成功且已交付的 `instance/staging/migration-*` 隔离测试负载；保留报告与回执，失败/未知/活动目录保护。
4. 无角色/引用的已交付历史程序展开目录及安装缓存。签名原件独立保护；唯一原件另按必要程序＋每月1份最多12个月规则轮换。开发别名链接阻止目标删除，不新增链接或复制回大文件。
5. 完整 `.tmbackup` 普通旧点：必须存在最近完整恢复的原始认证/恢复证明，且旧点有可信来源、无活动/恢复引用，才回收。恢复源及最后可用点优先于数量设置。频率选择不等于删光恢复材料。

隔离演练补充：报告含自足v2结构证据、source_unchanged=true且程序已经完成交付，或其源码已合入当前正式提交时，可以在原生锁内核查并回收release/shared负载，保留原始报告。复制期间数据变化类失败，只在同一包后来有通过的v2演练、且该包已有可信交付回执时回收shared不一致副本；未重新验证的代码继续保留。结构失败、没有成功替代证明、旧版恢复证据依赖隔离DB的现场均不套用。此规则不删正式DB或正式附件。

原生备份因普通身份进程检查受限而留下的 `backup_work_retained`，复用当前签名程序 `retained_recovery_cleanup.close_locked` 完成认证收尾：核对同一加密备份及所有者回执、完整恢复清单与每件SHA、隔离库完整性和原生进程引用，在原维护锁内删除可再生的独立恢复副本，随后用保留原所有权的CAS/持久化审计关闭标记。未知、变化、故障或没有原始证明的现场保留并停止本次维护。此入口不停止服务，不删加密备份，不改业务库。

仅维护日志轮转8MiB×3；正式 server.log 沿用实际运行包已经启用的8MiB×3进程内轮转。业务审计、数据库伴随文件、Docker卷、系统快照、Codex数据、个人文件和全局uv缓存不进入本策略。

## 在线点与恢复

私有目录：`/Library/TianmingERP-OnlinePoints`，服务499所有、权限700，刻意放在原生 `instance/backups` 外，防止旧整包恢复格式门禁拒绝未知子目录。

- `.tmdb`：原生 DB-only 加密格式，SQLite online backup、一致性/外键/版本检查、解密解包复核。
- `.tmdb.json`：私有配对回执，绑定DB密文SHA、程序SHA、加密文件清单 `.tma` 的名称与SHA。
- `.tma`：按非DB文件完整内容集合寻址的加密清单，相同内容集合只保存一份。
- `objects/<plain-sha>.tmobj`：变化文件的认证加密内容；新对象必须完整独立解密比对，复用对象逐件核对密文SHA。源码运行依赖、OCR模型和缓存由保留签名程序提供，不重复打包。

文件在捕获或在线快照期间变化时，本次不发布。新点回执持久化后才保留最新3份DB点、回收不再被保留点引用的文件集合与对象；任何未知/损坏回执阻止附件回收。失败保留最后可用点。

恢复函数 `file_points.restore_isolated(point, store, password, fresh_target, signed_program, public_key)` 只能写全新隔离目录，拒绝正式根目录。验证签名程序、配对清单、逐件对象、DB结构合同及附件引用；不启动服务。实际迁移恢复必须由授权维护流程选择新点并切换，不能直接把 `.tmdb` 当完整 `.tmbackup` 交给旧恢复入口，不覆盖新订单。

## 状态与停用

`/Library/TianmingERP-LocalMaintenance/cleanup-status.json` 记实际删除/保留；`backup-status.json` 记最近成功及连续失败；`paired-restore-proof.json` 记一次实际隔离恢复结果。私有 `OnlinePoints/backup-status.json` 保存细分结果。失败保留原件，不以未验证文件轮换。

仅停用新增维护任务可经现有管理员授权 `launchctl bootout system/cn.tianming.erp.local-maintenance` 和 `launchctl bootout system/cn.tianming.erp.online-backup`；应同时移走这两个专用plist才永久停用。不要删除ERP系统服务plist，不要自动撤销旧每日定时器的暂停门禁。更改资产需先停用这两个专用任务、重新固化审核SHA，再安装和完整试跑；不得修改整个正式目录归属。

2026-10-20补充：root保护的完整发布及原生备份收尾final-result.json，与已验证签名manifest、源码、版本、revision、备份SHA及关闭结果全部一致时，也可登记技术交付。仅签名发布、健康状态或未关闭报告不能据此判完成；失败/未知/活动任务继续保护。
